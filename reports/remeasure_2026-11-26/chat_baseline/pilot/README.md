# 채팅 AI 기준선: 버린 시험 실행 (채점에 쓰지 않음)

본 측정(`../run1`~`../run3`) 전에 스크립트 결함 때문에 버린 실행이다. 결과를 숨기지 않으려고 모두 남긴다.
점수는 아래 결함 때문에 채팅 AI의 실력이 아니라 실험 장치의 문제를 반영하므로 문서 숫자에 쓰지 않는다.

## v1 (1회, `v1/run1`, 점수 0/6, 스크립트 `v1/chat_baseline_v1.py`)

- 사용자 역할 모델이 명령 결과(루트 활동 153줄 등)를 직접 옮겨 적다가 출력 한도(8,000토큰)에서 잘렸다. 채팅 AI는 "메시지가 39번째 줄에서 잘렸다"고 답했다.
- 사용자 역할이 "WAF/ALB 결과는 다음 메시지로 보내겠다"고 미룬 직후 최종 보고서 요청이 붙어, 채팅 AI가 요청한 WAF·ALB 결과를 받지 못했다.
- 사용자 역할이 묻지 않은 로그 종류(WAF·ALB)를 먼저 알려 줬다(원래 실험 조건과 다름).
- 2·3회차는 위 결함을 보고 중간에 멈췄다(결과 파일 없음).

## v2 (3회, `v2/run1`~`run3`, 점수 0/6, 3/6, 0/6)

v1을 고친 것: 명령 결과는 스크립트가 원문 그대로 붙임(`send` 표시), 미루기·묻지 않은 로그 소개 금지.

- 채팅 AI 호출의 출력 한도(8,000토큰)를 긴 생각이 다 써서 **빈 답**이 대화에 들어갔다. run1은 3번째·최종 답이 비어(`transcript.json`의 길이 0) 보고서가 없었고, run3은 3번째 답이 비었다. 스크립트가 빈 답을 오류로 처리하지 않았다.
- run2(3/6)는 빈 답이 없었지만, 같은 장치로 잰 3회 중 1회만 정상이라 함께 버렸다.

## v3에서 고친 것 (본 측정)

- 모든 호출을 출력 한도 64,000토큰·스트리밍으로 받고, 한도에서 잘리거나 빈 답·거절이면 그 실행을 실패로 멈춘다(빈 답을 대화에 넣지 않음).

## v3 (3회 시작, 모두 실패, `v3_credit_error/`)

고친 스크립트(`scripts/chat_baseline.py`)로 3회를 동시에 시작했지만, 대화 도중 API가
`400 credit balance is too low`(크레딧 부족)로 거절했다. 결과 파일은 없고 오류 기록만 남긴다.
크레딧을 채운 뒤 같은 명령으로 3회를 다시 돌린다.

## 액세스 키 표시

공방전 로그의 액세스 키는 `convert_gongbang.py`가 만든 가명이지만, 비밀값 검사(gitleaks)를 통과하도록 이 폴더의 기록은 키를 앞 8자·뒤 4자만 남겼다(예: `ASIA71C2…95CF`, LogFinder 화면과 같은 모양). 그 밖의 대화 내용은 고치지 않았다. 스크립트도 같은 방식으로 저장한다. 보관한 v1 스크립트 사본의 채점용 키 한 곳도 같은 방식으로 가렸다(지금 스크립트는 정답지 파일에서 읽는다).
