# 정규화·산출물 점검 (2026-11-01)

> 질문: 로그 8종이 한곳으로 들어올 때 서로 다른 형식이 같은 의미로 맞춰지는가, 그리고 보고서가 바로 이해되는가.
> 방법: 8종(CloudTrail, VPC Flow, WAF, ALB, SSH, 서버 방화벽, nginx, GuardDuty)을 한 폴더(`samples/combined`, 합성 데이터)에 넣고
> 공통 필드를 로그별로 비교한 뒤, 보고서를 PC·모바일·다크 모드로 캡처해 검토했다. 고친 뒤 같은 방법으로 다시 점검했다.

## 1. 정규화에서 찾은 문제와 수정

| # | 문제 | 영향 | 수정 |
| --- | --- | --- | --- |
| 1 | 결과 표기가 로그마다 다름(Success, ACCEPT, ALLOW, COUNT, BLOCK, detected) | 같은 "막힘"을 규칙마다 따로 판단해야 함 | 공통 필드 2개 추가: `status`(성공/실패/알 수 없음), `disposition`(허용/차단/탐지/판단 없음). 대소문자 무관 |
| 2 | ALB 행위가 전체 URL(`GET http://host:port/path`) | 웹서버 로그(`GET /path`)와 같은 요청이 다른 값 | ALB도 `메서드 경로?쿼리`로 맞추고 호스트·포트는 따로 저장 |
| 3 | HTTP 상태 코드 필드 이름·형식이 다름(ALB `elb_status` 문자열, nginx 문자열) | 404 판단 규칙이 한쪽에만 적용 | 둘 다 `http_status` 정수로 통일 |
| 4 | SSH·방화벽 로그(연도·시간대 없음)를 2026년·UTC로 고정 | 내년 로그나 한국 시간 서버에서 시각이 9시간 틀어져 다른 로그와 안 엮임 | 올해(미래면 작년)로 보고, `--year`, `--syslog-tz +09:00`으로 지정. 쓴 가정은 보고서에 표시 |
| 5 | WAF가 이미 **차단한** 요청도 "SQL 인젝션 패턴"으로 탐지 | 이미 막힌 공격이 위험으로 부풀려짐 | 차단된 요청은 패턴 규칙에서 제외(차단 사실은 별도 규칙으로 낮음 표시) |
| 6 | 네트워크·웹 로그에는 대상 서버 ID가 없음 | "어느 서버가 공격받았나"가 보고서에 안 나옴 | 설정 스냅샷의 서버 IP로 대상 서버 ID를 채움(사건 묶기 연결고리로는 쓰지 않음) |
| 7 | GuardDuty 결과의 단계가 이름 앞부분으로만 정해짐(자격증명 유출이 "초기 침투"로 분류) | 공격 흐름 순서가 어긋남 | 같은 의미의 LogSight 규칙이 있으면 그 단계·기법·한국어 이름을 씀 |
| 8 | GuardDuty 시각을 "마지막 발견"으로 사용 | 처음 일어난 때보다 늦게 표시돼 흐름 순서가 뒤바뀜 | "처음 발견" 시각을 쓰고 마지막 발견은 따로 보관 |
| 9 | 소수점 아래 자릿수가 3·6자리가 아닌 시각(예: `.1Z`)을 Python 3.10에서 못 읽음(CI에서 발견) | 해당 줄이 조용히 빠짐 | 자릿수를 6자리로 맞춘 뒤 읽음 |

## 2. 보고서에서 찾은 문제와 수정

| 문제 | 수정 |
| --- | --- |
| 첫 화면에 전문 용어 숫자 카드 7개(의심 표시, 탐지 결과, 공격 유형 등) | 카드 4개(검토할 사건, 높음, 중간·낮음, 읽은 이벤트)와 한 문장 요약. 바로 아래 **"먼저 할 일"**: 모든 사건의 수정안을 우선순위 순으로 5개 |
| 해석 가정이 보이지 않음 | **"이렇게 해석했습니다"** 상자(시간대·연도, 설정 스냅샷 유무, ALB 뒤 nginx IP 주의) |
| "원인 설정"과 "수정안"이 같은 내용을 두 번 나열 | **"원인과 수정안"** 한 카드로: 무엇이 문제 → 왜 → 근거 → 적용·되돌리기 명령(접힘) |
| 근거 목록이 길면 가로로 넘침 | 줄바꿈, 6개 넘으면 "외 N건"으로 접기 |
| 근거 이벤트 표가 화면을 넘치고 결과가 영어 원문(accept, BLOCK) | 결과를 차단·허용·성공·실패·탐지로 표시(COUNT·404 같은 뜻 있는 원문만 덧붙임), 규칙도 한국어 이름, 표는 기본 접힘 |
| 흐름 문장의 "(대상: IP)"가 공격 대상처럼 읽힘 | "(기준: IP)"로 변경 |
| UTC만 표시 | "04:10~04:30 UTC (한국 13:10~13:30)" |
| 모바일(390px)에서 긴 탐지 이름 때문에 가로 스크롤 | 긴 단어 줄바꿈, 표만 안에서 가로 스크롤. 페이지 폭 390px 확인 |
| 다크 모드에서 사건 링크가 거의 안 보임 | 링크 색을 테마 강조색으로 |

## 4. 남은 한계
- ALB 뒤 nginx 로그의 출발지는 ALB 내부 IP라서 ALB 로그와 자동으로 엮이지 않는다. nginx 로그 형식에 X-Forwarded-For를 넣어야 한다(보고서에 안내).
- SSH 로그에는 대상 IP가 없어 서버 ID를 채우지 못한다(호스트 이름 → 인스턴스 매핑은 설정 스냅샷에 아직 없음).
- 합성 데이터로만 점검했다. 실제 계정 로그로 같은 점검을 다시 해야 한다(실습 계정 준비 후).
