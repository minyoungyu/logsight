# "그냥 채팅 AI"로 공방전 사건 풀기 (기준선 실험)

실험일 2026-11-03 · 데이터: 공방전 통합로그 가명본(CloudTrail 10,223 · WAF 432 · ALB 122) · 정답지 `reports/ctf/gongbang_ground_truth.json`

## 한눈에 보기

- **채팅 AI는 3번 주고받은 끝에 공격 6단계 중 3단계를 맞혔다. LogSight는 5단계를 맞혔다.** 둘 다 G3(PDF 내려받기)는 놓쳤다.
- 채팅 AI는 **CloudTrail만 봤다.** WAF나 API Gateway 로그는 한 번도 달라고 하지 않았다. 그래서 공격이 **어떻게 들어왔는지(G1·G2)를 찾지 못했다.** SSRF는 "가능성"으로만 남았다.
- 반대로, 잡은 부분은 꽤 잘 풀었다. 서버 역할 키가 외부 IP 두 곳에서 쓰였고, 워크플로 9회 실행은 성공, SSM 4회는 거부됐다는 것을 시각과 함께 정확히 짚었다. 지어낸 사실은 없었고, 모르는 것은 "미확인"으로 표시했다.
- **"원본은 너무 커서 AI가 거절한다"는 논리는 이 실험에서 성립하지 않았다.** 채팅 AI는 로그 통째가 아니라 필요한 조회 명령만 시켰다. 그래서 거절도, 길이 초과도 없었다.

## 방법

- **채팅 AI**: 이 프로젝트와 무관한 새 Claude 세션. 도구를 쓰지 않고 붙여 넣은 내용만 읽게 했다(Claude 채팅 앱과 같은 조건). 모델은 LogSight AI 재검토 측정과 같은 계열이다.
- **사용자**: Claude(이 스레드)가 "보안을 모르는 백엔드 개발자" 역할을 맡았다. 첫 메시지는 "13:30 이후 공격받았을 수 있다는 연락을 받았다. 무슨 일이 있었고 뭘 고쳐야 하나". 그 뒤로는 AI가 시킨 명령의 결과만 가명 로그에서 뽑아 줬다. 데이터에 없는 것(인스턴스 설정, us-east-1, GuardDuty 탐지 결과, 비용)은 "확인 못 함"으로 답했다.
- **사용자가 알려 준 사실**: blue-team-1·2는 팀원 계정이고 대응 작업도 팀원이 했다는 것, PatchSignal은 원래 있던 서비스라는 것, 이 계정이 공방전 환경이라는 것. LogSight 측정에서도 "블루팀 운영자" 목록을 같은 정보로 넣었다.
- 3번 주고받은 뒤(약 30분 분량) 보고서를 받고 끝냈다.

## 단계별 결과

| 단계 | 내용 | 채팅 AI | LogSight (규칙+AI) |
|---|---|---|---|
| G1 | 웹앱에 내부 주소 조회 요청(WAF 차단) | 놓침 (SSRF를 가능성으로만 언급) | 잡음 |
| G2 | 서명 없는 토큰으로 EKS 지원 API 접근 | 놓침 | 잡음 |
| G3 | PageSnap 결과 PDF 내려받기 | 놓침 | 놓침 |
| G4 | EC2 역할 키를 외부 IP에서 사용 | **잡음** | 잡음 |
| G5 | 그 키로 워크플로 실행 성공 | **잡음** (9회, 시각 정확) | 잡음 |
| G6 | 그 키로 SSM 시도(거부) | **잡음** (4회 모두 AccessDenied) | 잡음 |
| 합계 | | **3/6** | **5/6** |

G7~G9는 입력 로그에 없는 단계라 두 쪽 모두 채점하지 않았다.

## 관찰

1. **막힌 곳은 "로그를 엮는 것"이었다.** 채팅 AI는 CloudTrail 안에서는 뛰어났지만, 웹(WAF) 로그를 같이 보자고 하지 않았다. 웹 침투와 키 탈취가 같은 공격자 대역이라는 연결(LogSight의 INC-002)은 서로 다른 로그를 맞춰 봐야 보인다.
2. **사용자 부담이 컸다.** jq가 들어간 CLI 명령을 6개 이상 실행해야 했다. 결과 표가 깨지면 다시 보내야 했다. "어느 계정이 팀 것인가" 같은 판단도 사용자에게 돌아왔다. 이번에는 Claude가 사용자 역할을 해서 명령을 대신 정확히 돌렸다. 실제 비전문가라면 여기서 시간이 더 걸리거나 멈췄을 가능성이 크다. **이 실험은 채팅 AI 쪽에 유리한 조건이다.**
3. **확인하지 않은 주장이 하나 있었다.** "팀원 계정은 이 IP들을 쓰지 않았다"는 문장은 실제 데이터와는 맞았다. 하지만 AI가 팀원 IP 목록을 본 적은 없다. 근거를 대조하는 장치가 없으면 이런 문장을 걸러낼 수 없다.
4. **조치 제안은 일반론과 구체안이 섞였다.** IMDSv2 강제, 역할 세션 무효화, `aws:SourceVpc` 조건처럼 실제로 쓸 만한 제안이 나왔다. 하지만 인스턴스 설정을 못 봐서 "IMDSv2가 꺼져 있다면" 같은 조건부 문장에 머물렀다.

## LogSight에 주는 의미

- "그냥 AI에 물어보면 된다"는 반론에 대한 답은 **"원본이 너무 크다"가 아니다.** **"채팅 AI는 사용자가 꺼내 준 로그 한 종류 안에서만 추리하고, 다른 로그와 엮지 못한다"**가 이번 실험이 보여 준 답이다.
- 사람이 해야 하는 일(명령 실행, 결과 붙이기, 계정 구분)을 줄이는 것도 LogSight의 가치다. 이 부분은 실제 사용자 테스트로 시간을 재야 숫자가 된다.
- 한계: 1회 실험, 사용자 역할도 AI가 맡았고, 채팅 AI도 Claude다. 중간보고서에는 "예비 실험"으로 표기한다.
