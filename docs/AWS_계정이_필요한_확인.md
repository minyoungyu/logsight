# AWS 계정이 있어야 하는 남은 확인 두 가지 (2026-11-24)

약점 1-A(GuardDuty 조사 에이전트와 나란히 비교)와 8-B(실계정 경보→통지 기록)의 남은 부분이다. 둘 다 사람이 AWS 계정에서 해야 한다. 자동 격리는 쓰지 않는다(`--respond` 없이, 출품 범위 밖).

## 1. 8-B: 이미 한 것과 남은 것

- **이미 했다.** 2026-11-06 실제 계정에서 경보 → 보고서 → 디스코드 → 자동 격리까지 돌았다([시연_실계정.md](시연_실계정.md) "실제 계정 시연 결과").
- **남은 것은 시간 측정 하나다.** 그때 경보 도착은 "약 1~5분"으로 어림했고 정밀하게 재지 않았다.

재는 법(30분, 1달러 미만, [시연_실계정.md](시연_실계정.md)의 준비·스택을 그대로 씀):

1. `python -m logsight watch ...`를 `--respond` 없이 켠다.
2. 시연용 빈 보안그룹에 22번을 연다. 명령을 친 시각(t0)을 적는다.
3. CloudTrail 이벤트의 `eventTime`(t1), `watch`가 메시지를 받은 시각(t2. 화면 출력에 시각이 없으면 report.html 파일이 생긴 시각), 디스코드 카드 도착 시각(t3, 메시지 시각)을 적는다.
4. 3번 반복하고 규칙을 지운다.

| 회차 | t0 → t1 (CloudTrail 기록) | t1 → t2 (EventBridge·SQS) | t2 → t3 (분석·통지) | 합계 |
|---|---|---|---|---|

결과는 [시연_실계정.md](시연_실계정.md)의 "약 1~5분"을 바꿔 적는다.

## 2. 1-A: GuardDuty 조사 에이전트와 같은 사건을 나란히

목적: "GuardDuty는 시도를 알리고, LogFinder는 뚫렸는지 판정한다"([핵심_차별점.md](핵심_차별점.md))를 말로만 두지 않고 같은 사건에서 보인다.

**먼저 확인할 것(미확인).** [비슷한_제품_비교.md](비슷한_제품_비교.md)에 적은 대로 조사 에이전트는 2026-07 공개 미리보기다. 서울 리전에서 켜지는지, 한국어로 답하는지, WAF·ALB·서버 로그를 읽는지는 확인하지 못했다. 계정 콘솔에서 먼저 본다. 서울에 없으면 미리보기가 있는 리전에서 한다.

절차(반나절):

1. 시험 계정에 GuardDuty를 켠다(30일 무료 체험). 조사 에이전트 미리보기를 켠다.
2. 같은 공격을 낸다. 후보는 GuardDuty가 결과를 내는 것과 내지 않는 것을 하나씩.
   - GuardDuty가 낼 것: 시험용 키를 다른 IP(예: CloudShell 밖 PC)에서 써서 권한 탐색. 결과가 나오는 데 시간이 걸린다(최대 몇 시간, 미확인).
   - GuardDuty가 못 볼 것: 저장소의 `samples/injection/inject_ko` 같은 웹 침투 로그. 이것은 계정에 올리지 않고 LogFinder에만 넣는다. 조사 에이전트에 이 질문을 하면 무엇이라 답하는지 적는다.
3. 같은 사건에 대해 두 쪽에서 받은 답을 아래 칸에 그대로 옮긴다. 고치지 않는다.

| 질문 | 조사 에이전트 답 | LogFinder 답 | 근거(로그 줄)가 붙었나 |
|---|---|---|---|
| 공격이 있었나 | | | |
| 실제로 성공했나(키 생성·로그인·데이터) | | | |
| 무엇을 먼저 해야 하나 | | | |
| 로그가 없어 모르는 것은 | | | |
| 걸린 시간, 비용 | | | |

4. 조사 에이전트가 더 나은 칸이 있으면 그대로 적는다. 이 비교는 "우리가 이긴다"를 보이려는 것이 아니라 겹치는 곳과 안 겹치는 곳을 나누려는 것이다.
