# 공개 데이터셋으로 잰 탐지 성능 (독립 측정)

자체 테스트 사이트(lab)에서 낸 재현율 100%는 규칙을 만든 사람이 시나리오도 만든 결과다.
여기서는 **남이 만들고 남이 라벨한** 공개 데이터셋으로 같은 엔진을 잰다.
규칙·파서는 하나도 바꾸지 않았다. 프로필에는 사이트 설명(로그 경로, 자기 호스트 이름, syslog 연도)만 적었다.
측정은 규칙만 쓴다(AI 호출 없음).

## 한눈에 보기

| 측정 | 공격 단계 탐지 | 줄(요청) 단위 재현율 | 정밀도 | 오탐률 | 비고 |
|---|---|---|---|---|---|
| 자체 lab (11/26 재측정) | 34/35 | - | - | 정상 트래픽 오탐 0건 | 시나리오를 규칙 작성자가 만듦. 결과 `reports/remeasure_2026-11-26/lab/eval.json`([재측정](재측정_2026-11-26.md)) |
| AIT-LDS v2.0 russellmitchell, 침해된 서버 | **3/7** | 98.7% (7,639/7,739) | 98.2% | 1.8% (142/7,969) | 잡은 건 스캔 3단계뿐, 실제 침투(웹셸 업로드·명령 실행)와 권한 상승은 놓침 |
| AIT-LDS v2.0, 공격 라벨 없는 웹서버 | - | - | - | 0.2% (129/65,290줄), IP 4/6 | 129줄 중 12줄은 실제 공격자 nmap(데이터셋 라벨 누락) |
| HTTP CSIC 2010 | - | - | - | - | **공식 사이트 접속 불가로 측정 못 함** |

**결론: 줄 단위 98.7%는 dirb·wpscan이 남긴 7,600여 줄의 스캔 소음이 만든 숫자다.**
공격 흐름으로 보면 정찰 3단계만 잡았고, 서버를 실제로 장악한 단계(wpDiscuz 업로드 취약점으로 웹셸 올림 → 웹셸로 명령 32회 실행 → su·sudo 권한 상승)는 하나도 잡지 못했다.
전체 판정도 거꾸로 나왔다. 실제로 침해된 intranet_server는 "의심(suspicious)", 공격 라벨이 없는 webserver는 Nextcloud 오탐 때문에 "침해 가능성 높음(likely_breached)"이었다.
자체 lab의 100%는 일반화되지 않는다.

## 1. AIT-LDS v2.0 (russellmitchell 테스트베드)

- 데이터: 가상 회사망에서 정상 사용자 시뮬레이션 4일 + 다단계 공격 1회. 공격 단계별로 로그 줄에 라벨이 붙어 있다.
- 받은 것: 테스트베드 zip(7.1GB)을 통째로 받지 않고 HTTP Range 요청으로 웹(apache2)·인증(auth.log) 로그와 라벨만 41MB 꺼냈다. 디스크에 zip은 남지 않는다.
- 호스트: `intranet_server`(WordPress, 공격 대상), `webserver`(메일·Nextcloud 리버스 프록시, 공격 라벨 없음), `cloud_share`.
- 재현: `python scripts/public/fetch_ait.py --out data/public/ait` → `python scripts/public/eval_ait.py --data data/public/ait --out reports/public/ait_russellmitchell.json`
- 결과 원본: [`reports/public/ait_russellmitchell.json`](../reports/public/ait_russellmitchell.json)

### 공격 단계별 (intranet_server)

| AIT 라벨 | 라벨 줄 | 표시한 줄 | 판정 | 걸린 규칙 |
|---|---|---|---|---|
| service_scan (nmap) | 12 | 6 | 탐지 | WEBLOG_SCANNER, WEBLOG_ENUM_404 |
| dirb (경로 대입) | 4,485 | 4,447 | 탐지 | WEBLOG_ENUM_404, WEBLOG_SENSITIVE_FILE |
| wpscan | 3,199 | 3,186 | 탐지 | WEBLOG_SCANNER, WEBLOG_ENUM_404 |
| webshell_upload (wpDiscuz CVE-2020-24186) | 3 | 0 | **놓침** | - |
| webshell_cmd (웹셸로 명령 실행) | 32 | 0 | **놓침** | - |
| attacker_change_user (su) | 4 | 0 | **놓침** | - (auth 파서가 su 줄을 읽지 않음) |
| escalated_command (sudo) | 5 | 0 | **놓침** | - |

놓친 이유(코드를 고치지 않고 원인만 기록):

1. **웹셸 업로드**: `POST /wp-admin/admin-ajax.php` 200 한 줄뿐이다. 접속 로그에는 본문이 없어서 정상 댓글 요청과 구별되지 않는다. lab의 XXE·저장형 XSS와 같은 사각지대다.
2. **웹셸 명령 실행**: `/wp-content/uploads/2022/01/<임의>.php?wp_meta=<base64 명령>` 형태다.
   - `WEBLOG_UPLOAD_EXEC`는 업로드 폴더를 `/uploads`, `/upload`, `/files`, `/data`로 시작하는 경로로만 본다. WordPress의 `/wp-content/uploads/`는 해당이 안 된다.
   - `SHELL_PARAM`은 `cmd`·`exec` 같은 이름만 보고, 명령이 base64라 `CMDI` 패턴에도 걸리지 않는다.
   - 응답이 매번 약 500KB였는데 `WEBLOG_LARGE_EXFIL`은 같은 요청이 공격 패턴이나 관리자 경로에 걸렸을 때만 보므로 걸리지 않았다.
3. **권한 상승**: auth 파서가 sshd·sudo·useradd만 읽는다. `su` 줄은 이벤트가 되지 않고, sudo 줄은 이벤트는 되지만 sudo 단독으로 걸리는 규칙이 없다.

### 오탐

| 호스트 | 규칙 | 줄 | 원인 |
|---|---|---|---|
| intranet_server | WEBLOG_AUTH_BRUTE | 142 | 정상 사용자의 wpDiscuz 댓글 갱신(`POST /wp-admin/admin-ajax.php`)이 `/wp-admin` 접두사 때문에 관리자 로그인 시도로 세어짐 |
| webserver | WEBLOG_WEBSHELL_ACCESS | 117 | Nextcloud 미리보기 `/remote.php/dav/...?c=<해시>`의 `c=` 인자를 웹셸 명령 인자로 봄 |
| webserver | WEBLOG_LARGE_EXFIL | 5 | 위 오탐 요청 뒤의 큰 이미지 응답 |

`cloud_share`는 접속 로그가 `vhost_combined` 형식(줄 앞에 `호스트:포트`)이라 29,795줄 중 9줄만 읽혔다. 이 형식을 읽지 못하는 것도 결과로 남긴다.

### IP 단위 (ctf_evaluate.py 형식)

`scripts/ctf_evaluate.py`와 같은 정답 형식(`measure.score`)으로도 쟀다. 라벨 줄의 IP를 공격, 나머지 IP를 정상으로 뒀다.

| 호스트 | 재현율 | 정밀도 | 오탐률 |
|---|---|---|---|
| intranet_server | 1/1 | 50% | 1/5 정상 IP |
| webserver | - | 0% | 4/6 정상 IP |

**이 숫자는 참고만 한다.** 이 테스트베드에서는 외부 VPN 사용자와 공격자가 같은 방화벽 NAT 주소(172.19.131.174)로 들어온다. 공격 IP가 곧 정상 사용자 IP라서 IP 단위 재현율 100%는 의미가 없다. 실제 CTF 정답 파일도 팀 NAT를 쓰면 같은 문제가 생긴다.

## 2. 판정 수정 후 재측정 (2026-10-26)

1절 결과를 보고 규칙 네 개와 판정 기준 하나를 고쳤다(`logsight/web/webdetect.py`, `logsight/web/webanalyze.py`).
고칠 때 본 russellmitchell로 다시 잰 숫자는 독립 측정이 아니다. 그래서 고칠 때 보지 않은 **santos** 테스트베드로도 쟀다.
santos는 같은 종류의 공격(WordPress 침투)을 다른 환경·다른 사용자 활동에서 재현한 데이터다. 그래서 "다른 환경에서도 통하는가"는 보여 주지만, "다른 종류의 공격도 잡는가"는 보여 주지 못한다.

| 데이터 | 서버 | 실제 | 수정 전 판정 | 수정 후 판정 | 공격 단계 | 오탐 줄 (전 → 후) |
|---|---|---|---|---|---|---|
| russellmitchell (고칠 때 봄) | intranet_server | 침해됨 | 의심 | 침해 확인 | 3/7 → 4/7 | 142 → 1 |
| russellmitchell (고칠 때 봄) | webserver | 정상 | 침해 가능성 높음 | 근거 없음 | - | 129 → 12 |
| **santos (처음 봄)** | intranet_server | 침해됨 | 침해 가능성 높음 | **침해 확인** | 3/7 → 4/7 | 1,073 → 71 |
| **santos (처음 봄)** | webserver | 정상 | 침해 가능성 높음 | **침해 가능성 높음 (여전히 틀림)** | - | 64 → 5 |

santos에서 새로 나온 오탐(고치지 않음): Nextcloud 파일 이름이 백업 파일로 걸림(5줄, 판정을 올림), WordPress `load-styles.php?c=0`이 웹셸 접근으로 걸림(55줄), 로그인 화면 `redirect_to=https://`가 RFI로 걸림(13줄).
santos를 보고 이것들을 고치면 santos도 독립 측정이 아니게 된다. 고친 뒤에는 세 번째 테스트베드로 잰다.

결과 원본: `reports/public/ait_russellmitchell_after_fix.json`, `reports/public/ait_santos_before_fix.json`, `reports/public/ait_santos.json`

## 2-2. 정상 웹 요청 오탐 줄이기 (2026-11-20, 사양서 S7·NFR-12)

목표는 정상 웹 요청 줄 중 표시된 줄 0.1% 이하다. 10/27 처음 본 fox는 0.18%(302/163,782)였다.
이 PR 직전 main(#42 포함)에서 다시 재면 0.136%(223/163,782, `ait_fox_before_fix.json`)였다. 분모는 10/27과 같다(10/27 결과에도 `cloud_share` 46,977줄이 이미 들어 있다).
> 2026-11-26 정정: 여기에는 원래 "vhost_combined를 읽게 되면서(#41) cloud_share 4만 줄이 새로 들어왔고 11/20 main 기준 fox는 0.30%"라고 적혀 있었다. 0.30%를 담은 결과 파일이 없고, cloud_share 설명은 10/27 결과 파일과 맞지 않아 지웠다(`docs/근거_점검_2026-11-26.md` R2).
이번에 고친 것은 두 PR이다.

- #42(웹셸 접근·RFI): 숫자만 있는 `c=0`을 명령으로 보지 않고, 우리 사이트로 돌아오는 `redirect_to`를 RFI로 보지 않는다.
- 이 PR(백업 파일·관리자 접근):
  - 백업 파일 노출은 내려받는 요청(GET·POST)만 본다. Nextcloud 사용자가 WebDAV로 `unit.zip`을 올리고(PUT) 살피고(PROPFIND) 지운(DELETE) 줄이 걸렸다.
  - 내부망 IP의 관리자 접근은 같은 IP의 **다른** 공격 신호 앞뒤 1시간 안의 것만 알린다. fox에서는 공격자와 VPN 직원이 같은 NAT 주소(172.17.130.196)를 써서, 공격 며칠 전후 직원의 WordPress 관리 작업까지 걸렸다. 관리자 접근 요청 자체에서 나온 신호(로그인 기록 없는 관리자 페이지)는 다른 신호로 치지 않는다.

| 테스트베드 | 이 수정에서 | 수정 전(main, #42 포함) | 수정 후 | 재현율·잡은 단계 |
|---|---|---|---|---|
| fox | 원인을 보고 고침(개발 데이터) | 0.136% (223/163,782) | **0.029% (47)** | 같음(410,591/412,189줄, 5/7단계) |
| wheeler | 숫자만 잼. 다른 스레드가 #42 때 요약을 봄 | 0.065% (175/271,327) | **0.021% (57)** | 같음(431,293/432,906줄, 5/7단계) |

남은 오탐(fox 47줄, wheeler 57줄)의 성격:
- **라벨 누락으로 보이는 실제 공격**: 두 곳 모두 nmap 스크립트 엔진 요청 18줄(`/nmaplowercheck…`, `/HNAP1`, 공격 단계 시각표의 service_scan과 같은 시각). fox의 명령 삽입 1줄은 웹셸에 base64로 리버스 셸을 넘긴 요청이다. 이것들은 고치지 않았다.
- 업로드 폴더 안 웹셸의 썸네일(`…-225x300.php`)을 직원 브라우저가 미디어 화면에서 부른 줄(fox 4줄). 업로드 폴더에 실행 파일이 있다는 것 자체가 침해 신호라 그대로 둔다.
- fox 관리자 접근 25줄: 공격 신호 1시간 안에 같은 NAT 주소에서 들어온 직원 요청. 주소만으로는 구별할 수 없다. `trusted_ips`를 적으면 사라진다.
- wheeler `WEBLOG_ADMIN_FORGED` 31줄: 로그 기간 전에 로그인한 관리자로 보인다(#42 본문 참고).

**한계**: AIT 8개 테스트베드는 이제 모두 누군가 한 번은 보고 규칙을 고친 데이터다. 그래서 위 숫자는 개발 점수이고, 사양서 S7·NFR-12는 🟡(개발 데이터로만 달성)로 둔다. 손대지 않은 정상 트래픽(CSIC 2010 등)으로 재야 ✅로 바꿀 수 있다.

## 2-1. HTTP CSIC 2010

- 공식 사이트(`https://www.tic.itefi.csic.es/dataset/`)는 2026-10-25 측정 시점에 HTTPS 연결이 재설정되고, HTTP는 503(upstream connect timeout)을 돌려줬다. 세 번 다시 시도해도 같았다.
- 미러(Kaggle·GitHub 사본)는 출처를 확인할 수 없어 쓰지 않았다.
- 변환·측정 스크립트는 준비해 두었다: `python scripts/public/eval_csic.py --normal normalTrafficTest.txt --anomalous anomalousTrafficTest.txt --out reports/public/csic2010.json`
  - 원시 HTTP 요청을 Apache `combined` 줄로 바꾼다. 응답·IP·시각이 없어 요청마다 다른 IP, 200 응답, 1초 간격을 가정한다(같은 IP 연속 요청 규칙은 이 데이터로 잴 수 없다).
  - 실제 접속 로그에는 POST 본문이 없으므로 **본문 제외(현실)**와 **본문 포함(상한)** 두 번 잰다.
  - 합성 요청 4개로 변환이 맞는지만 확인했다. 실제 숫자는 사이트가 열리면 낸다.

2. M. Landauer, F. Skopik, M. Wurzenberger, W. Hotwagner, A. Rauber, "Have it Your Way: Generating Customized Log Datasets With a Model-Driven Simulation Testbed," *IEEE Transactions on Reliability*, vol. 70, no. 1, pp. 402–415, 2021. doi:10.1109/TR.2020.3031317

사용 범위: 대학 공동 주최 대회 출품(교육·학술, 비영리) 평가용으로만 쓴다.

### 데이터 취급 원칙

1. **배포물에 데이터셋을 넣지 않는다.** 배포 이미지(Dockerfile)는 `.dockerignore` 허용 목록 방식이라 `docs/`·`reports/`·`scripts/`가 빠진다. 이 규칙이 깨지지 않게 `tests/test_dataset_license.py`가 검사한다.
2. **데이터셋 로그 줄이나 라벨을 테스트 픽스처로 복사하지 않는다.** 회귀 테스트용 로그는 직접 만든다. 같은 테스트가 제품 코드·샘플에 데이터셋 내용이 섞이지 않았는지 검사한다.

- **HTTP CSIC 2010**: C. Torrano Giménez, A. Pérez Villegas, G. Álvarez Marañón, "HTTP data set CSIC 2010," CSIC, 2010. 이용 조건은 공식 사이트가 열리면 확인한다.

고친 뒤에는 **다른 AIT 테스트베드**(예: santos, fox)나 CSIC로 재야 한다.
후보: WordPress 업로드 경로(`/wp-content/uploads/`)의 `.php` 실행, base64 인자 명령, `su` 파싱, `admin-ajax.php`를 로그인 시도에서 빼기, 짧은 인자 `c=`의 웹셸 판정 조건, `vhost_combined` 형식 읽기.
