# 고객 설치: 버튼 하나, 서버 설치 없음, 로그는 LogSight가 보관

보안 담당자가 없는 팀이 대상이라, 고객이 할 일은 **AWS 콘솔에서 링크를 열고 "스택 생성"을 누르는 것** 하나로 줄였다.
고객 서버에는 아무것도 설치하지 않는다. 더하는 것은 AWS 계정 설정뿐이고, 스택을 지우면 모두 사라진다
(이미 보관된 로그는 보관 기간까지 남는다).

## 구조

    고객 계정 (버튼 하나: logsight-onboard.yaml)          LogSight 계정 (우리가 운영)
    GuardDuty·CloudWatch 경보·위험 API ─ EventBridge 규칙 ─→ 허브 이벤트 버스 → SQS → logsight watch
    CloudTrail(보관용 추적) ─────────────────────────────→ 보관 버킷(Object Lock) AWSLogs/<고객 계정>/
    VPC Flow Logs(고르면) ───────────────────────────────→        〃
    logsight-reader 역할(읽기 전용, ExternalId) ←──────────── 분석 서버가 설정 확인할 때만 빌림
    logsight-responder 역할(고르면, 격리 전용) ←────────────── 자동 격리(방안 A), 처음엔 시험 모드

로그를 우리가 보관하는 이유: 공격자가 고객 계정의 로그를 지워도, 우리 계정의 보관 버킷은 고객 계정 권한으로 지울 수 없다.
그래서 사고 뒤 "로그가 없어 분석이 막힌" 고객에게 보관본을 줄 수 있다(구상한 동작 흐름 6번).

## 순서

**우리 쪽(한 번):**

1. 보관 버킷: `deploy/aws/logsight-log-archive.yaml` (SourceAccountIds에 고객 계정을 더해 간다)
2. 허브: `deploy/aws/logsight-hub.yaml` (CustomerAccountIds에 고객 계정을 더해 간다)
3. `logsight-onboard.yaml`을 S3에 올려 https 주소를 만든다.
4. 분석 서버: `python -m logsight watch --queue-url <허브 QueueUrl> --s3 "s3://<보관 버킷>/AWSLogs/{account}/CloudTrail/{region}/{date}/" ...`
   `{account}`·`{region}`은 경보가 난 고객 계정·리전으로 바뀌어, 그 고객 폴더만 읽는다.

**고객마다:**

    python -m logsight onboard-link --template-url <3번 주소> --bus-arn <허브 IntakeBusArn> \
      --archive-bucket <보관 버킷> --principal-arn <분석 서버 역할 ARN> [--vpc-id vpc-...] [--isolation]

링크 두 개가 나온다. 1번(주 리전, 전체 설정)과 2번(us-east-1, 경보만: IAM 키·사용자 생성 경보는 AWS가 여기로만 보냄).
고객은 각 링크를 열어 맨 아래 IAM 확인란에 체크하고 "스택 생성"을 누른다. ExternalId는 고객마다 새로 만들고 우리 고객 기록에 저장한다.

## 고객이 알아야 할 비용

| 항목 | 비용 |
| --- | --- |
| EventBridge 규칙(AWS 서비스 이벤트) | 기본 버스는 무료. 다른 계정 버스로 보내는 것은 사용자 지정 이벤트로 과금될 수 있음(경보 건수만큼이라 작음, **미확인**) |
| 보관용 CloudTrail | 계정에 추적이 이미 있으면 관리 이벤트 두 번째 사본이 10만 건당 약 2달러. 걱정되면 `--no-trail`(대신 로그를 계정 안에서 지울 수 있게 됨) |
| VPC Flow Logs | 고를 때만. S3 전송 GB당 과금 |
| 보관 버킷 저장 | 우리 계정에서 냄 → 요금제에 반영 필요 |

## SSH 로그(auth.log)

서버에 설치하지 않으니 auth.log는 실시간으로 오지 않는다. 대신(아직 구현 전):
경보가 오면 SSM으로 그 서버의 auth.log를 가져오는 방법을 다음에 붙인다. SSM 에이전트는 Amazon Linux·Ubuntu 공식 이미지에
기본으로 들어 있지만, 계정 단위 설정(Default Host Management Configuration)을 켜야 하고 공격자가 먼저 지웠으면 못 가져온다.
`deploy/host/`의 Fluent Bit은 고객이 원할 때만 쓰는 선택 사항으로 남긴다.

## 아직 안 된 것

- 여러 고객을 한 분석 서버로 받을 때 **설정 확인(--collect-env)과 자동 격리는 아직 계정마다 역할을 바꿔 빌리지 않는다.**
  지금은 고객 하나에 분석 서버 설정 하나다. 계정 → 역할·ExternalId 표를 읽어 경보마다 그 고객 역할을 빌리는 것이 다음 일.
- 템플릿은 cfn-lint만 통과. **실제 계정에서 올려 본 적 없음.** 특히 us-east-1 규칙이 다른 리전 허브 버스로 보내지는지,
  보관용 추적이 다른 계정 Object Lock 버킷에 실제로 써지는지 확인해야 한다.
- 고객 로그를 우리가 보관하므로 개인정보 처리 위탁 계약, 보관 기간·파기 기준, 고객이 보관본을 요청하는 절차가 필요하다.
