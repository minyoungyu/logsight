# LogSight 중간보고 구현 요약 (2026-10-20 기준)

## 1. 현재 동작하는 것
- 로그 5종 파서: CloudTrail(JSON, JSON Lines, gzip, 폴더 일괄), VPC Flow Logs v2, AWS WAF, ALB, SSH auth.log. 파일 형식 자동 판별.
- 공통 스키마(Event): 시각, 출처, 출발지/대상 IP·포트, 주체, 인스턴스 ID, 액세스 키, 행위, 결과, 근거 위치(파일:줄).
- 규칙 기반 1차 탐지 20종(MITRE ATT&CK 대응). 예: CloudTrail 로깅 중지(T1562.008), 인스턴스 역할 자격증명의 외부 사용(T1552.005),
  IAM 사용자·키·권한 생성(T1098), 권한 탐색 연속 거부(T1580), 포트 스캔(T1046), WAF가 COUNT 모드로 통과시킨 SQL 인젝션(T1190), SSH 연속 실패 후 성공(T1078).
- 사건 묶기: 의심 이벤트만 그래프 노드로 넣고 IP·인스턴스·IAM 주체·액세스 키를 연결고리로 30분 창 안에서 연결. 나머지는 맥락 집계.
- 설정 점검: 보안그룹·NACL·WAF·EC2(IMDS)·IAM·CloudTrail 설정 스냅샷과 사건을 대조해 원인 설정, 현재→제안 값, AWS CLI 명령, 주의사항 생성.
- Claude 분석: 구조화 출력(JSON 스키마)으로 요약·공격 흐름·원인·수정안 우선순위·확인 불가 항목을 받는다. 키가 없거나 실패하면 규칙 기반 보고서로 대체.
- 환각 검증: AI가 든 근거(ref)가 실제 입력에 있는지 코드로 검사해 없는 근거는 분리 표시.
- 마스킹: 액세스 키(앞 8자만 남김), password/secret/token 값, 민감 필드명을 AI·보고서로 나가기 전에 가림.
- 출력: HTML 보고서(라이트/다크, 근거 로그로 바로 이동), JSON, CLI, FastAPI 웹 업로드 데모.

## 3. 실행 확인한 환경
| 환경 | 결과 |
| --- | --- |
| Python 3.10 / 3.11 / 3.12 / 3.13 / 3.14 (Linux) | 통과 |
| Alpine(musl), Debian 11·12·13 컨테이너 | 통과 |
| Amazon Linux 2023 + Python 3.10 | 통과 |
| Amazon Linux 2023 기본 python3(3.9) | 지원 안 함 → 안내 메시지로 종료하도록 수정 |
| Windows / macOS | GitHub Actions 설정 준비(저장소 생성 후 자동 실행) |

검증 중 고친 문제: Python 3.9 실행 시 이해하기 어려운 오류 → 버전 안내 메시지,
Windows 메모장 저장 파일(BOM, CRLF) 읽기 실패 가능성 → utf-8-sig로 읽고 테스트 추가,
웹 폼의 "AI 끄기" 체크박스가 전달되지 않던 문제 수정, 대용량에서 전체 마스킹 비용 → 외부로 나가는 데이터만 마스킹.
