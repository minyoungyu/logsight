# LogSight 중간보고 구현 요약 (2026-11-01 기준)

## 1. 현재 동작하는 것
- 로그 7종 + GuardDuty 탐지 결과 파서: CloudTrail(JSON, JSON Lines, gzip, 폴더 일괄), VPC Flow Logs v2, AWS WAF, ALB, SSH auth.log, 서버 방화벽 로그(iptables/nftables/ufw), 웹 서버 접속 로그(nginx/apache). 파일 형식 자동 판별.
- 공통 스키마(Event): 시각, 출처, 출발지/대상 IP·포트, 주체, 인스턴스 ID, 액세스 키, 행위, 결과, 근거 위치(파일:줄).
- 규칙 기반 1차 탐지 21종(MITRE ATT&CK 대응). 예: CloudTrail 로깅 중지(T1562.008), 인스턴스 역할 자격증명의 외부 사용(T1552.005),
  IAM 사용자·키·권한 생성(T1098), 권한 탐색 연속 거부(T1580), 포트 스캔(T1046), WAF가 COUNT 모드로 통과시킨 SQL 인젝션(T1190), SSH 연속 실패 후 성공(T1078).
- 사건 묶기: 의심 이벤트만 그래프 노드로 넣고 IP·인스턴스·IAM 주체·액세스 키를 연결고리로 30분 창 안에서 연결. 나머지는 맥락 집계.
- 설정 점검: 보안그룹·NACL·WAF·EC2(IMDS)·IAM·CloudTrail 설정 스냅샷과 사건을 대조해 원인 설정, 현재→제안 값, AWS CLI 명령, 주의사항 생성.
- Claude 분석: 구조화 출력(JSON 스키마)으로 요약·공격 흐름·원인·수정안 우선순위·확인 불가 항목을 받는다. 키가 없거나 실패하면 규칙 기반 보고서로 대체.
- 환각 검증: AI가 든 근거(ref)가 실제 입력에 있는지 코드로 검사해 없는 근거는 분리 표시.
- 마스킹: 액세스 키(앞 8자만 남김), password/secret/token 값, 민감 필드명을 AI·보고서로 나가기 전에 가림.
- 출력: HTML 보고서(라이트/다크, 근거 로그로 바로 이동), JSON, CLI, FastAPI 웹 업로드 데모.
- **분석 전 로그 점검(`logsight check`)**: CloudTrail·VPC Flow Logs·WAF·ALB 로그, GuardDuty, IMDSv2, 관리 포트 개방을 읽기 전용으로 점검하고 꺼진 항목마다 이유·비용·무료 대안·켜는 명령을 보여 준다. `--apply`로 동의한 항목만 켠다(CloudTrail, Flow Logs, GuardDuty).
- **설정 자동 수집(`logsight collect environment`)**: 보안그룹·NACL·WAF·인스턴스·IAM 정책·CloudTrail 설정을 읽어 설정 스냅샷을 자동 생성. 실제 계정에서도 수정안이 나온다.
- **무료 대체 수집**: CloudTrail 최근 90일 이벤트 기록(추적 없이 무료), 서버 방화벽 로그(VPC Flow Logs 대신), nginx/apache 로그(WAF 로그 대신). 비용 어림셈(`logsight cost`).

### flaws.cloud 전체 실행 전후 비교
| 항목 | 처음 | 수정 후 |
| --- | --- | --- |
| 처리 시간 | 13분 47초 | 1분 41초 |
| 최대 메모리 | 7.3GB | 2.7GB |
| 의심 표시 이벤트 | 1,513,840건(78%) | 527,220건(27%) |
| 가장 큰 사건 | 233,856건(8시간 이상 한 덩어리) | 18,474건(2시간 단위로 분할) |

고친 내용: 시간창 계산을 O(n) 슬라이딩 방식으로, 사건 연결을 UnionFind로, 사건 최대 길이 2시간,
이벤트당 저장 필드 축소, 실패한 인스턴스 생성(RunInstances)은 자원 탈취가 아니라 권한 거부로 분류.
남은 의심 표시의 대부분(46.6만 건)은 권한 없는 API 연속 시도로, 공개 CTF 계정이라 실제로 탐색 시도가 많은 데이터 특성이다.

웹 폼의 "AI 끄기" 체크박스가 전달되지 않던 문제 수정, 대용량에서 전체 마스킹 비용 → 외부로 나가는 데이터만 마스킹.

## 4. 아직 못 한 것
- Claude API로 실제 분석한 결과가 없다(API 키 대기). 지금 보고서는 모두 규칙 기반 모드.
- 정확도(정밀도·재현율)를 측정하지 못했다. flaws.cloud에는 정답이 없다.
- 점검·켜기 기능을 실제 AWS 계정에서 돌려 보지 않았다.

## 5. 2단계 계획(우선순위 순)
1. Claude 실제 분석 + 팀원 채점(단계·근거·수정안 실행 가능성 1~5점)
2. 실습 계정에서 Stratus Red Team으로 공격 기법 재현 → 정답지로 정확도 측정
3. 경보 더 줄이기: 알려진 정상 목록, 공격 유형별 요약 화면 (반복 묶기·점수 재설계는 완료)
4. GuardDuty 결과 입력은 완료(합성 예시로 확인). 실제 GuardDuty 결과로 확인
5. 파일 단위 스트리밍으로 메모리 절감, 수정안 영향 범위 표시 (기간 필터·되돌리기 명령·AI 전송 미리 보기는 완료)
