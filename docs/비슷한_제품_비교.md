# 비슷한 제품과 무엇이 다른가

조사일 2026-11-04. GitHub 공개 저장소는 저장소 페이지를 직접 열어 확인했다. AWS·상용 제품은 이 작업 환경에서 공식 사이트를
열 수 없어 **검색 결과 요약으로만** 확인했다(표에 "검색 요약"으로 표시). 별 수는 조사일 GitHub 검색 기준이다.

## 한 줄 결론

AWS 자체(GuardDuty 조사 에이전트, Detective)와 AI SOC 회사들이 같은 방향으로 가고 있다. LogSight가 다르게 하는 것은 세 가지다.

1. **GuardDuty가 읽지 않는 로그까지 한 사건으로 엮는다.** WAF·ALB·웹서버·SSH 로그와 CloudTrail·VPC Flow를 같이 본다.
2. **우리 팀 작업과 공격을 가른다.** 로그에서 우리 팀으로 보이는 계정을 찾아 한 번 확인받는다. 공방전에서 판정이 4/7에서 6/7로 올랐다(개발 데이터).
3. **보안 담당자가 없는 팀이 읽는 한 장.** 한국어로 쓰고, 문장마다 근거 로그(파일:줄)를 붙이며, 수정 명령과 "로그가 없어 모르는 것"을 함께 준다. AI 없이도 같은 형식으로 끝까지 동작한다.

## LogSight가 약한 곳 (숨기지 않는다)

- **성숙도:** 별·릴리스·외부 기여자가 없다. Suzaku는 규칙 796개, LogSight는 55개다.
- **처음 보는 데이터 탐지 범위 31%**(Splunk 표본 52개 중 16개). 개발에 쓴 데이터의 높은 점수는 실력이 아니다([처음보는데이터_측정.md](처음보는데이터_측정.md)).
- **AWS가 같은 일을 무료 미리보기로 시작했다.** 같은 판에서 싸우면 진다. 그래서 AWS가 읽지 않는 로그, 작은 팀의 맥락(우리 팀 알아보기), 한국어 한 장에 집중한다.
- 실제 고객 계정 시험 0회, 고객 인터뷰 0건, 비전문가 사용자 시험 0회.
