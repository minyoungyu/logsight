## 결과 (고치기 전 코드)

### Invictus AWS (Stratus 공격 재현 CloudTrail)

Stratus 실행 80번 중 상태 확인만 한 것(DescribeAccountAttributes) 34번과 되돌리기(StartLogging, 정책 삭제 등) 11번을 빼면 **공격 실행은 35번**이다.

| 결과 | 수 |
|---|---|
| 맞게 탐지 | 31 |
| 권한 거부 연속으로만 걸림(공격 호출이 실제로 실패: userData 읽기 15번은 권한 거부, GPU 인스턴스(p2.xlarge) 만들기 2번은 vCPU 한도 초과) | 3 |
| 놓침 | 1: 이름에 trail·log가 없는 CloudTrail 버킷에 1일 만료 수명 주기 규칙 |

- 고침: 같은 기록 안에서 CloudTrail 저장 버킷으로 확인된 버킷(CreateTrail·UpdateTrail의 `s3BucketName`, `cloudtrail.amazonaws.com`을 허용한 버킷 정책)에 만료 규칙을 걸면 `CT_LOGGING_TAMPER`로 잡는다. 고친 뒤에는 35번 중 32번을 맞게 탐지하고, 놓친 것은 0번이다(**개발 점수**).
- 라벨이 없는 호출 1,754건 중 352건이 표시됐다. 대부분 Stratus가 공격을 준비하면서 Terraform으로 만든 조회(`CT_DISCOVERY_BURST` 286건)와 만든 비밀값을 다시 읽은 것(`CT_SECRET_ACCESS` 62건)이다. 이 데이터에는 진짜 정상 사용이 거의 없어서 오탐률을 재는 데는 쓸 수 없다.
- 주의: LogFinder 규칙은 예전에 Stratus 기법 목록을 보고 만들었다. 그래서 데이터는 처음 보지만 행동은 이미 아는 것이다. 31/35는 그만큼 낙관적인 숫자다.

### CAM-LDS (리눅스 서버 침투 시나리오)

공격 단계마다, 그 시간 창에 LogFinder가 피해 서버의 웹 접근 로그·auth.log에서 무언가를 표시했는지 봤다.
'흔적 있음'은 그 시간 창에 공격자 IP의 웹 요청이나 sudo·su·sshd 줄이 있는 단계다. 흔적이 없는 단계는 이 두 로그로는 잡을 수 없다.

| 시나리오 | 공격 단계 | 흔적 있음 | 흔적 있는 단계 중 탐지 |
|---|---|---|---|
| 1 sudo_pam: 웹 스캔 → ZoneMinder 취약점 → www-data sudo → SSH 로그인 → `sudo cat /etc/shadow` | 27 | 13 | 7 |
| 3 ssh_apt: SSH 비밀번호 대입 → 패키지 저장소 오염(백도어 .deb) | 32 | 서버별 0~5 | reposerver 2/5 (SSH 대입·대입 뒤 성공), 다른 서버 0 |
| 4: 훔친 비밀번호로 이동 → `sudo -i` → `/usr/bin`에 파일 풀기 → 서비스 등록 | 22 | 서버별 2~13 | 0 |

- 잡은 것: 웹 스캔(nmap·nikto·ffuf), 웹 서비스 계정의 sudo, `sudo cat /etc/shadow`(어제 고친 규칙), SSH 비밀번호 대입과 대입 뒤 성공.
- 놓친 것: ZoneMinder 원격 실행(POST 본문에만 공격이 있어 접근 로그에 보이지 않음), 훔친 비밀번호로 한 정상 모양 로그인과 `sudo -i`, 서비스 등록·파일 숨기기(auth.log에 남지 않음).
- 시간 창으로 맞추기 때문에 한두 초 차이로 옆 단계의 표시가 들어올 수 있다. 엄밀하게 재려면 CAM-LDS의 로그 줄 대응표(manifestations)가 필요하다.
- 이 데이터의 공격 대부분은 audit 로그·syslog·Wazuh에만 흔적이 남는다. LogFinder는 그 로그를 읽지 않는다. 지금 범위(웹·auth·CloudTrail)의 한계가 숫자에 그대로 나온다.

### 실제 웹서버 로그 (Zenodo 20001206, 기관 x)

이벤트 219,154건 중 1,671건(0.76%)을 표시했다. 표시된 요청은 Struts OGNL, Fuel CMS 원격 실행, Shellshock, `/etc/passwd` 명령 삽입처럼 실제 인터넷 스캐너의 공격 문자열이다.
하지만 IP가 모두 한 값으로 가려져 있어서, '같은 IP의 404 연속' 같은 규칙은 모든 사용자를 한 사람으로 본다(`WEBLOG_ENUM_404` 1,182건은 부풀려진 숫자다). 라벨도 원작자의 패턴 규칙이라 정답으로 쓰기 어렵다.
