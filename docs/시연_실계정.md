# 실제 AWS 계정에서 경보 → 보고서 → 디스코드 시연

EC2 서버 없이, 무료 범위 안에서(1달러 미만) 실제 AWS 경보가 LogFinder를 거쳐 디스코드에 도착하는 것을 보여 준다.
LogFinder는 내 PC에서 돈다. AWS에 새로 만드는 것은 CloudTrail 추적, 경보 연동 스택, 시연용 보안그룹 셋이고 찍은 뒤 모두 지운다.

AWS 없이 같은 흐름을 먼저 돌려 보려면: `python scripts/demo_e2e_moto.py` (가짜 AWS, 아래 "AWS 없이 재현" 참고)

## 시나리오

"탈취한 키로 공격자가 방화벽에 SSH 뒷문을 연다"(ATT&CK T1562 방어 회피). 빈 보안그룹 하나에 22번 포트를 전체 인터넷에 연다.
서버를 붙이지 않으므로 실제로 열리는 곳은 없고, 바로 되돌릴 수 있다.

    공격(보안그룹 22번 개방) → CloudTrail 기록 → EventBridge 규칙(위험 API 호출) → SQS 대기열
      → 내 PC의 logsight watch가 가져감 → 설정 스냅샷 읽기(읽기 전용) → 분석 → report.html·summary.txt
      → 디스코드 카드 (관리자)

## 준비 (한 번)

1. 루트 계정 대신 IAM 사용자를 만들고 내 PC에서 `aws configure`로 키를 넣는다. 키는 채팅·화면·저장소에 남기지 않는다.
2. 저장소: `git pull && pip install -r requirements.txt`
3. 디스코드: 채널 편집 → 연동 → 웹후크 → 새 웹후크 → URL 복사

       echo '{"channels":[{"type":"discord","url_env":"LOGSIGHT_DISCORD_WEBHOOK"}]}' > notify.json
       export LOGSIGHT_DISCORD_WEBHOOK='https://discord.com/api/webhooks/...'   # Windows: $env:LOGSIGHT_DISCORD_WEBHOOK='...'
       python -m logsight notify-test notify.json        # 디스코드에 시험 카드가 와야 한다

4. CloudTrail 추적: 콘솔 CloudTrail → 추적 생성(관리 이벤트만). API 호출이 EventBridge 경보로 오려면 추적이 하나 있어야 한다.
   첫 추적의 관리 이벤트는 무료, S3 저장비는 몇 원 수준.

       aws sts get-caller-identity
       aws cloudtrail describe-trails --region ap-northeast-2

## 경보 연동 스택

    aws cloudformation deploy --region ap-northeast-2 \
      --template-file deploy/aws/logsight-alerts.yaml \
      --stack-name logsight --capabilities CAPABILITY_IAM
    aws cloudformation describe-stacks --region ap-northeast-2 --stack-name logsight \
      --query "Stacks[0].Outputs[?OutputKey=='QueueUrl'].OutputValue" --output text

만드는 것: SQS 대기열 2개(경보, 실패), EventBridge 규칙 3개, 읽기 정책. 기존 자원은 건드리지 않는다.
비용: SQS 월 100만 요청 무료(긴 폴링을 상시 돌려도 월 약 13만 요청), AWS 서비스 이벤트 규칙 무료.

## 감시 (터미널 1)

    python -m logsight watch --queue-url <QueueUrl> --region ap-northeast-2 \
      --collect-env --no-ai --notify notify.json --out reports/alerts

`--collect-env`는 경보 때마다 보안그룹 등 설정을 읽기 전용으로 읽어 "이 규칙을 닫아라" 수정안을 만든다.
Claude 판정·설명까지 보이려면 `--no-ai`를 빼고 `ANTHROPIC_API_KEY`를 설정한다(분석에 약 1분 더 걸린다).

## 공격 (터미널 2)

    SG=$(aws ec2 create-security-group --region ap-northeast-2 --group-name logsight-demo-sg \
          --description "LogFinder demo" --query GroupId --output text)
    aws ec2 authorize-security-group-ingress --region ap-northeast-2 \
      --group-id $SG --protocol tcp --port 22 --cidr 0.0.0.0/0

기대: 몇 분 안에 터미널 1에 `[분석] 위험 API 호출: AuthorizeSecurityGroupIngress ...` → 디스코드 카드 →
`reports/alerts/<시각>/report.html`. 출력의 "수신→보고서" 값이 분석 시간, "경보→보고서" 값이 AWS 전달 지연을 포함한 시간이다.

15분 안에 안 오면(추적 문제 등):
- CloudWatch 경보 강제: 아무 지표로 경보 `logsight-demo-high`를 만들고
  `aws cloudwatch set-alarm-state --alarm-name logsight-demo-high --state-value ALARM --state-reason demo` (경보 10개까지 무료)
- GuardDuty 샘플: GuardDuty 켜기(30일 무료 체험) → `aws guardduty create-sample-findings --detector-id <id> --finding-types UnauthorizedAccess:EC2/SSHBruteForce`.
  화면에 "[SAMPLE]"이 보이므로 "AWS가 만든 시험 결과"라고 말한다. 체험이 끝나기 전에 끈다.

## 정리 (찍은 직후)

    aws ec2 delete-security-group --region ap-northeast-2 --group-id $SG
    aws cloudformation delete-stack --region ap-northeast-2 --stack-name logsight
    # GuardDuty를 켰다면: aws guardduty delete-detector --detector-id <id>
    # 추적을 계속 둘 필요가 없으면 콘솔에서 CloudTrail 추적과 그 S3 버킷도 지운다

## 영상에서 말하지 않을 것

- 실제 계정 경보라고 확인되지 않은 것을 실제라고 하지 않는다(대체 경보를 쓰면 그렇다고 말한다).
- 웹후크 주소, AWS 키, 계정 번호가 화면에 나오지 않게 한다.

## AWS 없이 재현

    pip install "moto[sqs,s3]"
    python scripts/demo_e2e_moto.py      # 결과: reports/e2e_demo/

가짜 AWS에 대기열과 CloudTrail 로그 버킷을 만들고, 위와 같은 보안그룹 공격 이벤트와 GuardDuty 높음 경보를 넣는다.
2026-11-06 실행 결과:

    [3~6] watch 1회 처리: 2건, 0.6초
    [2 확인] 처리 뒤 대기열에 남은 메시지: 0개(분석 성공 후 지움)
    [6 알림] 임시 디스코드 서버가 받은 카드: 2개
    [7 격리] 9분 뒤 점검: 실행 0건(마감 전이라 기다림)
    [7 격리] 11분 뒤(아무도 확인 안 함): access_key AKIANEWATTACKER1 → would-do (시험 모드라 실제로 바꾸지 않음)
    [7 격리] 11분 뒤(아무도 확인 안 함): sg_rule sg-0demo0000000001|tcp|22|22|0.0.0.0/0 → would-do

보안그룹 경보는 중간 등급이라 격리 대상이 아니고, GuardDuty 높음 경보에서 도입 후 외부에서 만든 키와 22번 규칙만 골랐다
(원래 있던 키는 건드리지 않음).

## 실제 계정 시연 결과 (2026-11-06, 성공)

팀의 새 AWS 계정(ap-southeast-2, CloudShell)에 `logsight-alerts.yaml`을 처음 올려 끝에서 끝까지 확인했다.

- 공격: 보안그룹 22번, 이어서 3306번을 0.0.0.0/0에 개방, 로그 그룹 삭제(DeleteLogGroup)
- EventBridge 위험 API 규칙 → SQS → `watch` → 보고서 → 디스코드 카드(report.html 첨부) 도착
- 확인이 없자 자동 격리(실행 모드)가 연 규칙을 실제 계정에서 회수: `response.json` 상태 executed, 결과 done
- 시연 설정: 확인 기한 1분(기본 10분), CloudShell 관리자 권한으로 실행(격리 전용 역할 아님), AI 끔
- 경보가 오기까지 약 1~5분(정밀하게 재지 않음). 정밀 측정과 격리 전용 역할 검증은 2단계에서 한다.
