## 프리즈 전에 넣은 것과 이유

판단 기준은 세 가지다. (1) 시연 시나리오나 심사위원이 바로 해 볼 공격에서 놓치는가, (2) 비슷한 제품 세 개 이상이 기본으로 갖췄는가([사양서_외부비교.md](사양서_외부비교.md)), (3) 하루 안에 테스트까지 끝낼 크기인가. 셋 다 맞는 것만 넣었다.

| 넣은 것 | (1) 시연·심사 | (2) 외부 제품 | (3) 크기 | 결과 |
|---|---|---|---|---|
| **서버 권한 상승·계정 생성(FR-19)**: 웹 서비스 계정의 sudo·su, 셸 탈출 명령(find -exec 등), sudo 거부, useradd. sudo 줄을 직전 SSH 로그인 IP와 같은 사건으로 묶음 | 시연 흐름도와 CTF F4(웹셸 → sudo find로 root)가 '모르는 것'으로 비어 있었다. AIT 측정의 sudo 0/11·0/8, su 0/5 | Wazuh 기본 규칙, GuardDuty는 Runtime Monitoring을 켜야 봄 | 규칙 3개, 파서 보강 | 샘플 웹 사건에 'SSH 대입 → root 로그인 → 계정 생성'이 한 사건으로 이어짐 |
| **변형 인코딩·절대 경로 파일 열람**: %c0%ae·%u002e·전각 문자·이중 인코딩을 풀고, `file=/etc/shadow`처럼 ../ 없는 읽기도 경로 조작으로 봄 | 11/19 변형 17가지 시험에서 놓친 5개 중 2개. 필터 우회의 기본 기법이라 심사에서 해 볼 가능성이 큼 | Wazuh 웹 디코더 | 디코더 한 곳 | 두 엔진(사후 분석·웹서버 점검) 모두 잡음 |

### 측정 (모두 개발 데이터)

- 전체 테스트 **339개 통과**(이전 321개 + 이번 18개), ruff 통과. 저장소 샘플 4종 회귀 같음.
- Splunk attack_data 회귀: 처음 보는 데이터에서 잡았던 16개 **모두 유지**, 새로 잡음 10 → **13**(콘솔 로그인 3개). 놓친 목록을 보고 만든 규칙이라 **개발 데이터 점수(29/52)**이고, 처음 보는 데이터 점수 31%는 바꾸지 않는다.
- AIT·CSIC 오탐 재측정과 CTF 실제 로그 측정은 하지 않았다. 다음 작업(CTF 측정) 때 TC-HOST-07, TC-NFR-11로 잰다.

## 넣지 않은 것과 이유

| 후보 | 안 넣은 이유 |
|---|---|
| 가격 변조 탐지 | 정상 가격을 앱만 안다. 대부분 POST 본문으로 온다. 로그만으로 만든 규칙은 오탐만 늘린다. 사양서 '알려진 제약'에 적음 |
| POST 본문 공격(XXE·저장형 XSS·웹셸 내용) | 접속 로그와 WAF 로그 모두 본문이 없다. 앱 로그 연동은 새 입력 형식이라 프리즈 전 범위를 넘는다 |
| 다른 경로 IDOR 자동 추정 | 사이트 프로필에 경로를 적으면 이미 잡는다(TC-DET-06). 자동 추정은 상품 목록 넘겨 보기와 구별이 안 돼 오탐 위험이 크다 |
| 처음 보는 데이터 31% 끌어올리기 | 규칙을 더해도 처음 보는 점수는 새 데이터로만 잴 수 있다. 측정 작업(다음)으로 넘긴다 |
| OCSF 내보내기, Sigma 가져오기, 파일 무결성 감시 | [사양서_외부비교.md](사양서_외부비교.md) 3절 |
