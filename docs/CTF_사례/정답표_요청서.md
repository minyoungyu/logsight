# 공격 기록(정답표) 요청서 (참가 팀·운영진용)

> 받는 사람: 참가 팀(2인 1팀)과, 기록을 보관할 운영진 1명(판정하는 사람이 아닌 사람). 대회 시작 안내 때 나눠 준다.

안녕하세요. 11/26 CTF에 참가해 주셔서 감사합니다.

운영진은 대회 로그를 LogFinder(로그로 침해 흐름을 설명하는 도구)로 분석해, **도구만 보고 어떤 팀이 어디까지 침투했고 어떤 대응이 있었는지 얼마나 맞게 판단할 수 있는지** 재려고 합니다.
판정하는 사람이 먼저 결과를 봉인한 뒤에 이 기록과 맞춰 보기 때문에, **기록은 풀면서 바로 적어 주시고, 대회가 끝나면 보관 담당 운영진(○○○)에게만 내 주세요.**
판정하는 사람에게 풀이를 직접 알려 주지 말아 주세요(알려 주면 측정이 무효가 됩니다). 기록을 적었는지는 점수와 관계가 없습니다.

## 부탁드리는 것

1. **공격한 순간마다 한 줄씩** 적어 주세요. 나중에 기억으로 적으면 시각이 틀어집니다. 성공하지 못한 시도도 적어 주세요.
2. **운영진은 정상 작업과 대응을 적어 주세요.** 점검 접속, 서버 재생성, 힌트 공지, 보안그룹 변경, 차단 같은 일입니다. 오탐과 대응 판정을 재는 데 필요합니다.
3. **공격 IP**를 꼭 적어 주세요. 대회 중 IP가 바뀌었으면 바뀐 시각부터 새 줄에 적어 주세요.
4. 대회가 끝나면 보관 담당 운영진에게 내 주세요. 판정하는 사람은 봉인한 뒤에 보관 담당에게서 받습니다.

## 알아 두실 것

- 기록과 로그는 분석·측정에만 쓰고, 공개 자료에서는 IP와 팀 이름을 가립니다. ○○일 뒤에 지웁니다.
- 적기 어려운 항목은 비워 두셔도 됩니다. 시각과 IP만 있어도 대조할 수 있습니다.
- CTFd 제출 기록(팀·플래그·시각)도 보관 담당이 봉인 뒤에 함께 넘긴다. 플래그 제출 시각이 단계의 정답 경계가 된다.
- 받은 기록은 판정자가 LogFinder 정답 파일 형식(`ground_truth.json`, [CTF_로그_수집_가이드](../CTF_로그_수집_가이드.md) 3절)으로 옮깁니다.
  옮길 때 "로그에 흔적이 남는 공격인지(`detectable`)"는 판정 결과와 상관없이 표의 "한 일"만 보고 정하며, 애매하면 여쭤봅니다.
