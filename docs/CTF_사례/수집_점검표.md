# CTF 로그 수집 점검표 (11/26)

기존 [CTF_로그_수집_가이드](../CTF_로그_수집_가이드.md)를 이번 대회 일정에 맞춰 체크리스트로 줄인 것이다.
세부 명령과 정답 파일 형식은 가이드를 따른다. 대회 환경에 따라 **A(리눅스 웹 서버)** 또는 **B(AWS 계정)** 를 고르고, 둘 다면 둘 다 한다.

## 0. 대회 전에 확인할 것 (11/22~23)

- [ ] CTF 운영자에게 **로그 수집·분석 허가**를 받았다(메시지 캡처 보관). 대상은 대회 인프라뿐이다.
- [ ] 참가 안내에 "로그를 보관해 분석·성능 측정에 쓰고, ○○일 뒤 지운다" 문구가 들어갔다.
- [ ] 환경을 확인했다. 아래 빈칸을 채운다.

| 항목 | 답 |
|---|---|
| 서버가 AWS에 있나(계정 접근 가능?) / 학교·동아리 서버인가 | |
| 웹 서버 종류(nginx/apache), 로그 형식(`combined`인가) | |
| 프록시·로드밸런서 뒤인가(그렇다면 `X-Forwarded-For`가 남나) | |
| SSH가 열려 있나(auth.log 수집 대상) | |
| 서버 시각 시간대(UTC/KST) | |
| 팀별로 IP가 구분되나(한 NAT 뒤 여러 팀이면 사람 구분 불가) | |
| 대회 시간(시작~끝, 시간대 포함) | |
| 운영 측이 대회 중 하는 정상 작업(점검 접속, 재시작, 문제 초기화) | |

- [ ] 공격 팀에 [정답표_요청서](정답표_요청서.md)를 보냈고, **대회 중 실시간으로 적겠다**는 답을 받았다.

## A. 리눅스 웹 서버 (AWS 아님, 또는 AWS 위 EC2 한 대)

LogFinder가 읽는 것: 웹 접속·오류 로그, auth.log, 웹 루트 사본(웹셸 점검). **앱 자체 로그와 DB 로그는 못 읽는다.**

대회 전
- [ ] `head -1 /var/log/nginx/access.log`로 `combined` 형식 확인
- [ ] 로그 로테이션이 대회 중에 돌아도 `.1`·`.gz`를 함께 회수할 수 있게 계획(로테이션 주기 확인)
- [ ] 대회 시작 직전 웹 루트 사본을 하나 떠 둔다(대회 후 사본과 비교하면 올라온 웹셸이 보인다)

  ```bash
  sudo rsync -a --exclude='*.log' /var/www/<사이트>/ data/ctf-2026-11/webroot_before/
  ```

- [ ] (선택, 실시간 보관) 서버에 [deploy/host](../../deploy/host/) Fluent Bit를 깔아 S3로 1분마다 보낸다. 공격자가 로그를 지워도 남는다.
  AWS 보관 버킷이 있어야 하고 운영자 동의가 필요하다. 없으면 대회 직후 복사만 해도 된다.

  ```bash
  sudo bash deploy/host/install.sh <보관 버킷> ap-northeast-2 ctf-web
  python -m logsight heartbeat s3://<보관 버킷>/heartbeat/   # 대회 중 1시간마다
  ```

대회 직후 (가이드 2절)
- [ ] 로그 복사 + `SHA256SUMS` 남김. 원본은 건드리지 않는다.
- [ ] 웹 루트 사본(`webroot/`)을 다시 뜬다.
- [ ] `profile.json` 작성(가이드 4절 예시). `since`/`until`은 대회 시간, 시간대 포함.
- [ ] `python -m logsight scan --profile data/ctf-2026-11/profile.json --no-ai --out data/ctf-2026-11/report_rules`
- [ ] (AI 설명 포함본) 같은 명령에서 `--no-ai`를 빼고 `--out data/ctf-2026-11/report_ai`. **판정에 어느 쪽을 썼는지 보고서에 적는다.**

## B. AWS 계정 (CloudTrail·VPC Flow Log·GuardDuty)

대회 전
- [ ] 운영 계정에서 `python -m logsight check`로 로그가 켜져 있는지 확인(읽기 전용)
- [ ] 꺼져 있으면 운영자에게 [logsight-source-logging.yaml](../../deploy/aws/logsight-source-logging.yaml) 또는 [고객_설치](../고객_설치.md)의 버튼 하나 설치를 부탁한다.
  CloudTrail S3 데이터 이벤트(민감 버킷만)와 VPC Flow Log를 켠다. 비용은 [AWS_비용_계획](../AWS_비용_계획.md).
- [ ] (선택, 실시간 경보) `logsight watch`를 붙이면 대회 중 경보 → 보고서가 자동으로 나온다. 이 경우 **경보가 온 시각과 보고서가 나온 시각**을 사례 보고서에 적는다.
  자동 격리(`--respond`)는 대회를 망칠 수 있으므로 **끄거나 시험 모드로만** 둔다.

대회 직후
- [ ] CloudTrail 전달 지연(5~15분), Flow Log 지연(약 10분)을 기다린 뒤 회수
- [ ] `bash lab/aws/collect.sh <로그 버킷> <리전> <웹 서버 IP> [키]`를 대회 계정에 맞게 써서 `data/ctf-2026-11/`로 모은다(출력 폴더만 바꾼다)
- [ ] `python -m logsight analyze data/ctf-2026-11/<폴더> --env data/ctf-2026-11/<폴더>/environment.json --no-ai --out data/ctf-2026-11/report_rules`
- [ ] 운영 측이 쓰는 역할·사용자가 있으면 `python -m logsight team`으로 확인해 두고 `--team`으로 넣는다(정상 작업을 공격으로 짚지 않게). **이 확인도 정답표를 받기 전에 한다.**
