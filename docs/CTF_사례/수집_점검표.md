# CTF 로그 수집 점검표 (11/26, AWS)

대회는 AWS(시드니 `ap-southeast-2`, 대회 전용 계정)에서 [lab/ctf](../../lab/ctf/)의 Terraform으로 연다(PR #38).
로그는 LogFinder가 이미 읽는 종류만 쓴다. 구축 일정·비용·결정 사항은 "11/26 CTF 구축안 v2" 문서를 본다.

| 로그 | 어디에 쌓이나 | LogFinder 종류 | 무엇을 보나 |
|---|---|---|---|
| ALB 접속 로그 | logs 버킷 `alb/` | alb | 팀 포트로 들어온 모든 요청 |
| WAF 로그 | `aws-waf-logs-…` 버킷 | waf | 스캐너 차단, SQLi COUNT(F2) |
| nginx 접속·오류 | logs 버킷 `hosts/tNN/` (1분마다) | weblog, weberror | F1~F3, F5(SSRF) |
| auth.log | 같은 곳 | sshauth | F4 sudo |
| VPC Flow v5 | logs 버킷 `vpcflow/` | vpcflow | 팀 서버 간 이동, 바깥 연결 시도 |
| CloudTrail(+플래그 버킷 데이터 이벤트) | logs 버킷 `cloudtrail/` | cloudtrail | F6: 팀 역할 키를 VPC 밖에서 사용 |
| 설정 스냅샷 | `lab/aws/to_environment.py` | environment.json | 수정안(IMDSv1, 역할 권한, WAF COUNT) |

GuardDuty는 무료 플랜에서 막혀 있어 쓰지 않는다. F6은 CloudTrail로 판정한다(`CT_INSTANCE_CRED_OUTSIDE`).

## 0. 대회 전 (11/22~23)

- [ ] 운영 허가와 참가 안내 문구("로그를 시드니 리전에 보관, 분석·측정에 쓰고 12월 말 삭제") 확인
- [ ] [정답표_요청서](정답표_요청서.md)를 팀 수만큼 준비하고, 기록을 모을 보관 담당 운영진(판정자가 아닌 사람)을 정했다
- [ ] `bash aws/check_free_plan.sh`(프로젝트 파일) 로 vCPU 한도·무료 플랜 상태 확인. vCPU가 22 미만이면 팀 수를 줄인다(구축안 v2 참고)

## 1. 배포 직후 (리허설 11/24, 본 배포 11/25 밤 또는 11/26 아침)

- [ ] `terraform output -json buckets`로 logs·waf 버킷 이름 기록
- [ ] 5~15분 뒤 버킷에 `alb/` `vpcflow/` `cloudtrail/` `hosts/t01/nginx-access/`가 생겼는지 확인
- [ ] WAF 버킷에 파일이 생겼는지 확인
- [ ] 운영진 PC에서 t01을 F1~F6까지 한 번 풀고(황금 샘플), 아래 3절 명령으로 LogFinder 보고서가 나오는지 확인
- [ ] 위 황금 샘플 시각을 적어 두고, 대회 데이터에서는 그 시간대를 "운영진 검증"으로 뺀다

## 2. 대회 중 (11/26)

- [ ] 1시간마다 `aws s3 ls s3://<logs>/hosts/ --recursive | tail` 로 팀 서버 로그가 계속 올라오는지 확인
- [ ] 운영진 작업(서버 재생성, 힌트 공지, 보안그룹 변경)은 시각과 함께 [정답표_요청서](정답표_요청서.md)의 정상 작업 표에 적는다
- [ ] 팀 서버를 다시 만들면(`apply -replace`) 시각과 팀을 적는다
- [ ] 나는 참가자 풀이 채팅방과 CTFd 관리자 화면의 제출 기록을 보지 않는다(판정 전 정답 노출 방지)

## 3. 끝나고 (대회 종료 30분 뒤)

```bash
# 늦게 오는 로그(CloudTrail 최대 15분, Flow 약 10분)를 기다린 뒤
python lab/ctf/collect_logs.py --logs-bucket <logs> --waf-bucket <waf> \
    --region ap-southeast-2 --out data/ctf-2026-11
python lab/aws/to_environment.py --region ap-southeast-2 --out data/ctf-2026-11/environment.json

# 판정용 보고서(규칙만, 재현 가능)
python -m logsight analyze data/ctf-2026-11/analyze --env data/ctf-2026-11/environment.json \
    --year 2026 --no-ai --out data/ctf-2026-11/report_rules
# (선택) AI 설명 포함본: --no-ai 를 빼고 --out data/ctf-2026-11/report_ai
```

- [ ] `collect_logs.py`가 팀별 `nginx-access`·`auth` 파일을 만들었고, "끊김"이 있으면 그 팀과 시각을 적었다(참가자가 root로 로그를 비운 흔적일 수 있다)
- [ ] `raw/SHA256SUMS`가 생겼다. 원본(raw/)은 고치지 않는다
- [ ] CTFd 제출 기록 CSV는 **봉인 뒤에** 내보낸다(정답표와 같은 취급)
- [ ] `data/`가 `git status`에 나오지 않는다
- [ ] 수집이 끝났으면 `terraform destroy`(로그 버킷은 남는다), 콘솔에서 EC2·ALB·WAF·엔드포인트 0개 확인
- [ ] 다음은 [사례_보고서_양식](사례_보고서_양식.md) 1~3절(봉인)까지 쓴다

## 알려진 한계 (보고서 7절에 그대로 적는다)

- 팀 서버의 sudo 기록(F4)에는 공격자 IP가 없어, LogFinder가 웹 침투 사건과 다른 사건으로 따로 보여 줄 수 있다. 같은 서버·시각으로 사람이 잇는다.
- 메타데이터(169.254.169.254) 호출은 VPC Flow에 남지 않는다. F5는 nginx의 SSRF 요청으로만 보인다.
- 시드니 단일 리전 추적이라 IAM 등 전역 이벤트 일부는 빠질 수 있다. F6 판정에 쓰는 S3 데이터 이벤트는 남는다.
