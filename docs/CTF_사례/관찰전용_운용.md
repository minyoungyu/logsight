# 11/26 CTF: LogFinder를 관찰 전용으로 운용하기

결정(2026-11-24): 대회 중 LogFinder를 직접 돌려 운영자 입장에서 써 보되, **차단·격리 기능은 쓰지 않는다.**
LogFinder는 보고서와 통지만 만들고, 참가자 서버·계정·네트워크에는 아무것도 바꾸지 않는다.

## 1. 끄는 것과 확인 방법

| 기능 | 어떻게 꺼져 있나 | 대회 전 확인 |
|---|---|---|
| 자동 격리(키·역할·사용자 비활성) | `watch`·`on-alert`에 `--respond`를 주지 않으면 격리 코드가 불리지 않는다(`logsight/__main__.py`) | 실행 명령에 `--respond`가 없는지 운영 메모에 그대로 적어 둔다 |
| 격리용 쓰기 역할 | `deploy/aws/logsight-responder.yaml`을 대회 계정에 올리지 않는다 | CloudFormation 스택 목록에 `logsight-responder`가 없는지 |
| 로그 켜기 자동 적용 | `logsight check --apply`를 쓰지 않는다(읽기 전용 점검만) | — |
| 보고서의 수정·격리 명령 | 보고서에 명령은 나오지만 사람이 실행해야 한다. 대회 중에는 **아무도 실행하지 않는다** | 운영진에게 한 줄 공지 |

수정안이 대회 진행을 바꾸면(예: 공격 IP를 NACL로 막음) 참가 팀의 풀이와 로그가 달라져 비교 평가가 깨진다. 그래서 운영진이 문제 운영상 꼭 해야 하는 조치(서버 재생성 등)는 LogFinder와 상관없이 하고, 했다면 시각과 내용을 운영 기록에 남긴다.

## 2. 대회 중 돌리는 것

| 시각 | 할 일 | 남길 것 |
|---|---|---|
| 대회 전 | 황금 샘플(F1~F6 한 번 풀기) 로그로 `analyze`를 돌려 보고서가 나오는지 확인 | 보고서, 걸린 시간 |
| 대회 중 1시간마다 | 그때까지 모인 로그로 `analyze --no-ai`(규칙만) 한 번. 수집이 살아 있는지도 같이 본다 | 보고서 사본(시각을 이름에), "운영자로서 이 보고서를 보고 무엇을 하려 했나" 한 줄 |
| 대회 중 | 경보 통지(디스코드)를 켜 둘 수 있다. 통지는 운영진 채널로만 | 통지 도착 시각 |
| 대회 후 | 전체 로그로 최종 보고서 두 벌: 규칙만, 규칙+AI | 해시를 봉인 기록에 |

대회 중에는 AI를 켜지 않는다. 참가자 IP와 요청이 외부 API로 나가는 것을 대회 끝까지 미루고, 최종 분석에서만 가명 처리한 사건 요약을 보낸다(참가 안내문에 적은 범위 안에서).

"1시간마다 한 줄" 기록은 사용자 평가가 0회라는 약점의 작은 대체물이다. 실제 사고 대응자처럼 보고서를 보고 무엇을 하려 했는지, 그게 맞았는지를 대회 뒤에 정답표와 맞춰 본다.
