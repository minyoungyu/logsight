# 11/26 CTF 사례 보고서 묶음

11/26 CTF에 LogFinder를 연결해 두고, 대회가 끝난 뒤 **LogFinder 보고서만 보고** 어떤 침해가 있었고 어떤 대응이 있었는지를 적는다.
그다음 공격 팀의 정답표와 맞춰 본다. "실제 사건에 써 봤다"는 고객 관점 근거를 만드는 것이 목적이다.

개발자가 자기 도구를 평가하는 셈이라, 아래 세 가지를 지켜야 근거로 쓸 수 있다.

1. **판정을 먼저 봉인하고 정답표는 그 뒤에 받는다.** 봉인은 보고서 파일의 해시를 시각이 남는 곳에 올리는 것으로 한다.
2. **걸린 시간, LogFinder가 놓친 것, 잘못 짚은 것을 숨기지 않는다.** 좋은 숫자만 남기면 심사에서 오히려 약점이 된다.
3. **보안을 모르는 1~2명에게 같은 보고서를 보여 주고 판정 시간을 잰다.**
