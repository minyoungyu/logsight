## 4. 차이에서 생기는 위험

1. **신청서가 약속한 "핵심 증거"가 빠져 있다.** 신청서는 "내 AWS 계정에서 공격 5종을 재현해 정답지로 채점"을 핵심 검증으로 내세웠다. 지금 AWS 쪽 근거는 합성 샘플과 IP가 익명화된 flaws.cloud(정답지 없음)뿐이다.
2. **이야기의 중심이 바뀌었다.** 신청서의 한줄소개는 "흩어진 AWS 로그"인데, 최근 작업은 웹서버 쪽에 몰려 있다. 중간보고서에서는 웹서버 엔진을 "EC2 웹서버 로그(4종 중 하나)를 깊게 보는 부분"으로 AWS 흐름 안에 묶어 설명해야 문제 정의 점수를 잃지 않는다.
3. **PR 두 개가 열려 있다.** 합쳐지지 않으면 중간보고서에 쓸 기능이 main에 없다.
4. **멘토링·협업 15점**: 멘토링 기록과 팀원 역할 분담(김유찬 님 담당: API 연동·대시보드) 근거를 보고서에 넣어야 한다. 저장소만으로는 확인할 수 없다.
