# 사용자 평가 진행 대본과 준비 체크리스트

[설계.md](설계.md)의 실험을 실제로 돌리기 위한 문서다. 사양서 v2의 S3·NFR-16(비전문가가 보고서로 판정·먼저 할 일을 답한다)을 재는 유일한 방법이라,
코드 프리즈 전에 **최소 3명(파일럿)**, 최종보고서 전에 **8명**을 목표로 한다. 3명에서 멈추면 결과에 "표본 3명, 경향만"이라고 적는다.

## 1. 팀이 준비할 것

| 할 일 | 누가 | 기준 |
|---|---|---|
| 참가자 모집 | 팀 | 개발·운영 경험은 있고 보안 담당 경험은 없는 사람. 팀원, 측정 데이터를 본 사람, CTF에 같이 나간 사람은 뺀다 |
| 진행자 | 팀 밖 1명(가능하면) | 아래 대본만 읽는다. 내용 질문에는 답하지 않는다 |
| 채점자 | 2명 | 답안의 조건 표시를 가린 채 [정답_채점기준.md](정답_채점기준.md)로 채점 |
| 시나리오 데이터 | 팀 | A: 공방전 가명 로그(`data/gongbang`), B: BOTSv3 AWS 부분(`scripts/public/botsv3_extract.py`) |
| 자료 묶음 | 스크립트 | `python scripts/study_prepare.py --scenario A=data/gongbang --scenario B=data/botsv3_aws --participants 8 --out study_kit` |
| 장소·시간 | 팀 | 1인 70분. 화면 녹화는 동의한 경우에만 |

`study_prepare.py`는 시나리오마다 `baseline/`(원본 로그만)과 `logsight/`(같은 로그 + 규칙 모드 보고서)를 만들고,
교차 배정표(`배정표.csv`)와 빈 응답 파일(`응답.csv`)을 만든다. 이름에 ground_truth·정답이 들어간 파일은 묶음에 넣지 않는다.

## 2. 동의서(읽어 주고 서명)

> 이 시험은 보안 로그 분석 도구가 사람의 판단을 돕는지 보려는 것입니다. 여러분을 평가하는 것이 아닙니다.
> 약 70분 동안 두 가지 사고 기록을 보고 질문에 답합니다. 언제든 그만둘 수 있습니다.
> 답안과 걸린 시간은 참가자 번호(P01 등)로만 기록하며, 이름과 연락처는 결과 파일에 남기지 않습니다.
> 사용하는 로그는 가명 처리된 실습·공개 데이터이며 실제 회사의 기록이 아닙니다.
> 결과는 AI:ON 2026 최종보고서와 발표에 번호로만 쓰입니다.

## 3. 진행 대본(그대로 읽기)

1. (5분) "사전 설문을 부탁드립니다. 경력, AWS를 써 본 정도, 보안 교육을 받은 적이 있는지만 묻습니다."
2. (10분, 연습) "연습용 작은 예제로 자료가 어떻게 생겼는지 먼저 보겠습니다. 정답은 알려 드리지 않습니다." → `samples/demo`
3. (최대 25분, 첫 번째) "어제 이 AWS 계정에서 이상한 일이 있었다는 신고를 받았습니다. 이 폴더의 자료만 보고 질문지에 답해 주세요.
   인터넷 검색은 하지 말아 주세요. 다 됐으면 말씀해 주세요." → 배정표의 첫 번째 폴더. 시작·끝 시각을 적는다.
4. (5분) 쉬기
5. (최대 25분, 두 번째) 3과 같은 말로, 배정표의 두 번째 폴더
6. (5분, 사후 설문) "어느 쪽이 더 쉬웠나요? 보고서에서 믿기 어려웠던 문장이 있었나요? 없어서 아쉬웠던 정보는요?"

진행자가 하지 않는 것: 힌트, 내용 설명, "잘하셨어요" 같은 평가, 25분 넘겨 기다리기.

## 4. 끝난 뒤

1. 답안지의 조건 표시를 가리고 번호만 붙여 채점자 2명에게 넘긴다.
2. 채점 결과를 `응답.csv`에 넣고 `python scripts/study_score.py study_kit/응답.csv`로 집계한다.
3. 결과(성공 기준을 넘었든 못 넘었든)를 사양서 S3·NFR-16 칸과 [코드프리즈_판단.md](../코드프리즈_판단.md) 회차 표에 적는다.
4. "믿기 어렵다", "모르겠다"고 한 문장은 이슈로 연다(제목에 `S3`).
