# LogSight 현재 문제점과 "왜 안 살까" (2026-11-01 기준)

> 지금까지 실제로 돌려 본 결과(샘플 4종, flaws.cloud 1,939,207건, 6개 OS 환경 테스트)를 근거로 정리했다.
> 근거가 측정값이 아닌 항목은 "추정"으로 표시했다.
>
> **2026-11-01 갱신**: 문제 4(설정 스냅샷)와 안 살 이유 3(로그가 없음)은 `logsight check`·`collect`·무료 대체 로그로 해결했다([로그_점검과_무료대체.md](로그_점검과_무료대체.md)).
> 나머지 문제의 해결 방안 비교는 [해결방안_조사.md](해결방안_조사.md)에 있다.

## 한 줄 결론

LogSight가 지금 가장 약한 곳은 "**정확한지 증명이 없다**"와 "**AWS가 비슷한 기능을 이미 공짜로 준다**" 두 가지다.
사게 만들려면 탐지 성능으로 GuardDuty와 겨루기보다, **비전문가용 한국어 해석과 바로 쓸 수 있는 수정안**에 집중해야 한다.

---

## 1. 현재 기술적 문제점

| # | 문제 | 근거 | 영향 | 해결 방향 |
| --- | --- | --- | --- | --- |
| 1 | **Claude 분석을 실제 API로 한 번도 돌려 보지 않음** | API 키가 없어 모든 실행이 규칙 기반 모드. Claude 경로는 가짜 응답으로만 테스트 | 핵심 차별점인 "AI 해석"의 품질을 아무도 본 적이 없음 | 키를 받아 상위 사건 10개에 실행하고 사람이 채점 |
| 2 | **정확도를 측정하지 못함** | flaws.cloud는 정답지가 없고 IP가 익명화되어 있음 | "잘 잡는다"를 숫자로 말할 수 없음. 심사에서 가장 먼저 찔릴 부분 | 샌드박스에서 직접 재현한 로그와 정답지로 정밀도·재현율 측정 |
| 3 | **경보가 너무 많음** | flaws.cloud에서 의심 표시 27%(52만 건), 사건 1,871건 | 보안 담당자 없는 팀이 1,871건을 볼 수 없음. 결국 안 보게 됨 | 사건 우선순위 상위 몇 개만 보여 주기, 규칙 임계값 조정, 반복 패턴 묶기 |
| 4 | **설정 스냅샷이 없으면 수정안이 0개** | flaws.cloud 실행에서 수정안 0개. environment.json을 손으로 써야 함 | "방화벽 수정안 제안"이라는 핵심 가치가 실제 계정에서는 거의 안 나옴 | 읽기 전용 권한으로 보안그룹·NACL·WAF·IAM을 자동 수집하는 스크립트 |
| 5 | **CloudTrail 외 로그는 대용량 검증이 없음** | VPC Flow, WAF, ALB, SSH 파서는 몇 줄짜리 샘플로만 확인. WAF는 실제 로그 샘플이 없음 | 실제 로그 형식(사용자 지정 필드, v3~v5 Flow Logs)에서 깨질 수 있음 | 직접 만든 실습 환경에서 각 로그를 실제로 수집해 테스트 |
| 6 | **실시간이 아님** | S3에서 파일을 받아 올려야 분석됨 | 사고가 난 걸 알아챈 뒤에야 쓸 수 있음 | 2단계 이후: S3 이벤트로 자동 분석, 주기 실행 |
| 7 | **메모리를 많이 씀** | 194만 건에 2.7GB. 모든 이벤트를 메모리에 올림 | 노트북·작은 서버에서 몇 달치 로그는 어려움 | 날짜 범위 필터, 파일 단위 스트리밍 처리 |
| 8 | **수정안 일부가 덜 완성됨** | WAF 수정 명령에 `<LockToken>` 같은 자리표시가 남음. IAM 최소 권한 정책이 일반적 | 초보자가 그대로 따라 하기 어려움 | 실제 값으로 채운 명령 생성, 적용 전후 비교 화면 |
| 9 | **분석 도구 자체의 보안** | 웹 데모에 로그인 없음. 업로드한 로그가 서버에 남을 수 있음 | 보안 도구가 오히려 유출 경로가 될 수 있음 | 로컬 실행 우선, 웹은 인증과 업로드 즉시 삭제 |
| 10 | **세부 가정이 많음** | SSH 로그 연도 고정(2026), 모든 시각을 UTC로 가정, "가장 많이 쓴 IP = 정상" 같은 단순 기준 | 특정 환경에서 엉뚱한 결과 | 설정값으로 빼고, 가정을 보고서에 표시 |

## 2. 고객이 안 살 이유

대상 고객: 보안 담당자 없이 AWS를 쓰는 소규모 팀(학생 팀, 동아리, 작은 쇼핑몰, 초기 스타트업).

| # | 안 살 이유 | 설명 |
| --- | --- | --- |
| 1 | **AWS가 비슷한 걸 이미 준다** | GuardDuty는 30일 무료 체험이 있고, 인스턴스 자격증명 외부 사용 같은 탐지를 기본 제공한다. 2024년 12월에 나온 **Extended Threat Detection**은 여러 이벤트를 하나의 "공격 순서(attack sequence)"로 엮어 준다. LogSight의 사건 묶기와 정면으로 겹친다. AWS 발표 기준 GuardDuty 사용자에게 추가 비용 없이 켜진다. Amazon Detective도 그래프로 조사하는 기능이 있다. |
| 2 | **무료 오픈소스도 있다** | Prowler(설정 점검), Wazuh(로그 분석) 등. 전문가용이라 어렵긴 하지만 "공짜"라는 기준을 이기기 어렵다. |
| 3 | **고객에게 분석할 로그가 없다** (추정) | 작은 팀은 VPC Flow Logs, WAF, S3 데이터 이벤트를 안 켜 둔 경우가 많다. WAF는 돈이 들어 아예 없을 수 있다. 로그가 CloudTrail 관리 이벤트뿐이면 LogSight가 보여 줄 게 적다. |
| 4 | **사고가 나기 전엔 필요를 못 느낀다** (추정) | LogSight는 사후 분석 도구다. 사고 전에는 돈 낼 이유가 약하고, 사고가 나면 급해서 검증된 도구나 전문가를 찾는다. |
| 5 | **로그와 설정을 남에게 맡기기 불안하다** | 계정 읽기 권한을 주고 로그를 외부 AI(Claude API)로 보내야 한다. 학생이 만든 도구라면 더 불안하다. 개인정보가 들어 있는 로그라면 개인정보보호법·ISMS 관점에서도 걸린다. |
| 6 | **맞는지 증명이 없다** | 정확도 수치, 실제 사례, 사용자 후기가 없다(문제점 2번). |
| 7 | **결국 사람이 고쳐야 한다** | 안전을 위해 자동 적용을 안 하는데, 보안을 모르는 사용자는 CLI 명령을 받아도 적용을 망설인다. |
| 8 | **돈 낼 사람이 적다** (추정) | 대상 고객은 보안 예산이 거의 없다. 예산이 있는 회사는 이미 GuardDuty, Security Hub, 외부 관제 서비스를 쓴다. |
| 9 | **AWS 전용** | 국내 소규모 팀은 NCP, 가비아, 카페24, Vercel 같은 다른 플랫폼을 많이 쓴다(추정). |

## 3. 그럼 어디서 이길 수 있나

| 방향 | 내용 |
| --- | --- |
| **GuardDuty와 싸우지 말고 위에 얹기** | GuardDuty·Security Hub 탐지 결과(findings)를 입력으로 받아, 무슨 일이 있었고 무엇을 고칠지를 쉬운 한국어로 설명한다. "탐지는 AWS, 해석과 조치는 LogSight"로 포지셔닝한다. |
| **"한국어 설명 + 바로 쓰는 수정안"을 핵심으로** | GuardDuty 결과는 영어이고 전문 용어가 많다. 비전문가가 이해하고 따라 할 수 있는 설명이 차별점이다. |
| **교육 시장부터** | 대학 보안 수업, 공방전, 동아리처럼 "로그를 해석하는 법을 배워야 하는" 곳은 돈 대신 사용 실적을 쌓기 좋다. 팀의 공방전 블루팀 경험과도 맞는다. |
| **신뢰 문제를 구조로 해결** | 로컬 실행 기본, AI로 보내기 전 마스킹 결과 미리 보기, 근거 로그 검증 결과를 그대로 공개한다. |
| **정확도를 숫자로** | 직접 재현한 공격 5종 + 정답지로 "단계 판별 정확도 몇 %, 분석 시간 몇 분 → 몇 초"를 측정한다. |

## 4. 2단계 우선순위 제안

1. Claude API 키를 받아 실제 AI 보고서 생성, 사람이 품질 채점 (문제 1)
2. 샌드박스 재현 로그 + 정답지로 정확도 측정 (문제 2, 안 살 이유 6)
3. 읽기 전용 설정 자동 수집 → 실제 계정에서 수정안이 나오게 (문제 4)
4. 사건 우선순위 상위 N개만 보여 주는 화면 (문제 3)
5. GuardDuty 결과 입력 지원 (안 살 이유 1에 대한 답)

## 5. 심사 예상 질문과 답

- **"GuardDuty랑 뭐가 달라요?"**: GuardDuty는 탐지하고, LogSight는 설명하고 고칠 방법을 준다. 2단계에서 GuardDuty 결과를 입력으로 받아 같이 쓰는 구조로 간다.
- **"정확한가요?"**: 지금은 정확도를 측정하지 못했다. 공개 데이터(194만 건) 처리와 근거 검증 구조까지 확인했고, 2단계에서 정답을 아는 재현 데이터로 측정한다.
- **"누가 돈을 내요?"**: 처음엔 교육·공방전용 무료 도구로 사용 실적을 쌓는다. 이후 소규모 기업 대상으로 간다.
