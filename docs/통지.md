# 통지: 이메일·디스코드·슬랙·웹훅

경보 분석이 끝나면 `notify.json`에 적은 채널로 알린다. 넷 중 원하는 것만 남겨 쓴다.

    python -m logsight watch ... --notify notify.json
    python -m logsight notify-test notify.json      # 설정 확인용 시험 메시지

예시: `deploy/notify.example.json`. 웹훅 주소·SMTP 비밀번호는 환경변수에 넣고 설정에는 이름(`*_env`)만 쓴다.

| 채널 | 보내는 것 | 준비물 | 비고 |
| --- | --- | --- | --- |
| 이메일 | 제목 `[LogFinder 보안 경보·정보성] …`, 요약·먼저 할 일·자동 격리 예정, 마스킹된 보고서 HTML 첨부(5MB 이하) | SMTP 서버(예: Amazon SES SMTP, 회사 메일) | 본문 끝에 "정보성 알림, 광고 아님" 고지. 광고 문구 없음 |
| 슬랙 | 같은 요약 글 | 슬랙 앱의 Incoming Webhook 주소 | `<!channel>` 같은 전체 호출 문자는 무력화 |
| 디스코드 | 등급 색이 들어간 카드 + 보고서 HTML 첨부(8MB 이하, `attach_report: false`로 끔) | 채널 설정 → 연동 → 웹후크 주소 | `@everyone` 호출 막음 |
| 웹훅 | JSON 전체(경보, 사건, 먼저 할 일, 보고서 위치) | 받는 쪽 HTTPS 주소 | `secret_env`를 주면 `X-LogSight-Signature: sha256=HMAC(비밀, 시각.본문)` |
| 카카오 알림톡 | (예정) | 사업자 등록, 비즈니스 채널, 딜러사 계약, 템플릿 검수 | 지금은 `kakao_alimtalk`을 넣어도 "미지원"으로 기록만 |

공통: 채널마다 `min_severity`(기본 low), `enabled`(기본 true). 하나가 실패해도 나머지는 보내고 분석 결과는 그대로 남는다.
429·5xx는 3번까지 다시 보내고 4xx는 다시 보내지 않는다. 결과는 경보 폴더의 `run.json` `notify_channels`에 남는다.
통지에는 원본 로그·키를 넣지 않는다.

이메일을 정보성으로 두는 이유: 보안 경보는 고객이 계약한 서비스의 정보성 통지라 정보통신망법 제50조(광고성 정보 사전 동의)의
대상이 아니지만, 광고 문구가 섞이면 광고로 볼 수 있다. 그래서 제목과 본문 끝에 정보성임을 밝히고 판매·홍보 문구를 넣지 않는다.
법률 자문을 받은 판단은 아니다.

측정한 것: 슬랙·디스코드·웹훅 형식과 서명, 등급 거르기, 실패 처리는 이 PC 안의 임시 HTTP 서버로, 이메일은 SMTP를 흉내 내서 시험했다
(`tests/test_notify.py`). 실제 슬랙·디스코드·메일 서버로 보낸 적은 없다.
