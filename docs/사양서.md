# LogSight 간이 사양서 (v1.0, 2026-11-20)

멘토링(11/19) 지시에 따라 만든 1~2장짜리 사양서다. **지금 코드가 하는 일을 기준으로 적었고**, 외부 제품과 비교해 더할 것은
[사양서_외부비교.md](사양서_외부비교.md), 이 사양으로 만든 테스트 체크리스트는 [테스트_체크리스트.md](테스트_체크리스트.md),
코드 프리즈 판단은 [코드프리즈_판단.md](코드프리즈_판단.md)에 있다. 요구사항 ID(FR·NFR)는 테스트 케이스(TC)가 그대로 가리킨다.

## 1. 제품 정의

- **한 줄:** AWS 경보가 오면 흩어진 로그(CloudTrail·VPC Flow·WAF·ALB·웹서버·서버 인증)를 한 사건으로 엮어,
  공격인지 우리 팀 작업인지 가리고, 공격 흐름과 방화벽·설정 수정안을 근거 로그와 함께 한국어 보고서 한 장으로 준다.
- **사용자:** 보안 담당자 없이 AWS에 서비스를 올린 5~50명 팀의 개발자·운영자.
- **위치:** 24시간 감시(GuardDuty)의 **다음 단계**. 탐지 경보를 받은 뒤 "무슨 일이었고 무엇을 고치나"를 답한다.
- **범위 밖:** 실시간 차단(IPS), 로그 장기 보관·검색(SIEM), 설정 자동 수정(자동 격리 4종 제외), 요청 본문(POST body) 분석.

## 4. 알려진 제약 (사양에 일부러 넣지 않은 것)

- **POST 본문 안의 공격**(XXE, 저장형 XSS, 본문으로 보낸 가격 변조, 웹셸 업로드 내용): 접속 로그에 본문이 없다. WAF 로그에도 본문이 없다. 앱 로그가 있어야 한다.
- **가격 변조**: 정상 가격을 앱만 안다. 로그만으로는 판단 근거가 없어 규칙을 만들지 않았다.
- **다른 경로의 IDOR 성공**: 사이트 프로필의 `private_object_paths`에 경로를 적어야 잡는다(적지 않으면 상품 목록 넘겨 보기와 구별할 수 없다). 403/404를 연달아 받는 IDOR 탐색은 경로와 관계없이 잡는다.
- **커널 취약점 권한 상승**: auth.log에 남지 않는다.
