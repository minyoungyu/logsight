v1은 지금 코드가 하는 일을 받아 적었다. v2는 **제품을 만든 목적에서 출발**해 성공 기준을 먼저 정하고, 요구사항과 우선순위를 그 아래에 둔다.
코드가 못 하는 것은 ⬜(미구현·미달)로 솔직히 적는다. 요구사항 ID는 v1과 같게 두어 [테스트_체크리스트.md](테스트_체크리스트.md)의 추적을 유지했다
(`python scripts/spec_trace.py`). 외부 제품 비교는 [사양서_외부비교.md](사양서_외부비교.md), 프리즈 판단은 [코드프리즈_판단.md](코드프리즈_판단.md).

## 1. 문제와 목적

LogSight의 목적은 보안 담당자 없는 작은 팀이 경보를 받은 뒤 **1시간 안에 "공격인가, 어디가 뚫렸나, 무엇을 고치나"를 스스로 답하게 하는 것**이다.

- **문제.** CloudTrail, VPC Flow, WAF·ALB, 웹서버, auth.log가 다른 곳에 다른 형식으로 쌓여 하나씩 맞춰 봐야 한다. 공방전 블루팀에서 로그를 엮어 상황을 파악하는 데 막는 것보다 더 많은 시간이 들었다(신청서).
- **지금 도구로 안 되는 이유.** GuardDuty는 "이상하다"는 경보는 주지만 웹·서버 로그와 엮은 흐름, 원인 설정, 고칠 명령을 주지 않고 우리 팀 작업과 공격을 구별하지 않는다. 채팅 AI는 사용자가 무엇을 물을지 알아야 한다(기준선 실험: 공격 6단계 중 3단계, LogSight 5단계). SIEM·Wazuh는 운영할 사람이 필요하다.
- **이겨야 하는 지점은 탐지 개수가 아니다.** (1) 판정이 맞다 (2) 비전문가가 이해한다 (3) 근거가 있고 안전하다.

## 2. 목표 사용자와 사용 상황

| 사용자 | 알고 있는 것 | 모르는 것 | 바라는 것 |
|---|---|---|---|
| 주: 백엔드 개발자(보안 담당 경험 없음) | EC2·S3·IAM 기본, nginx 로그 | ATT&CK, CloudTrail 읽는 법, 무엇이 정상인지 | 공격인가, 먼저 할 일 3가지, 복사해 쓸 명령 |
| 부: 팀장·대표 | 서비스 영향, 고객 대응 | 기술 세부 | 피해 범위, 유출 여부, 보고서 한 장 |
| 부: 심사위원·멘토 | 보안 전문 지식 | 이 팀의 데이터 | 주장마다 측정 근거 |

- **U1 경보 뒤 분석**: 경보가 왔다. 로그를 올리거나 자동 분석을 받고, 1시간 안에 판정과 먼저 할 일을 정한다.
- **U2 웹서버가 뚫렸나**: 웹·인증 로그와 웹 루트로 "시도만 했나, 이미 뚫렸나"를 안다.
- **U3 로그가 없는 팀의 준비**: 꺼진 로그를 찾아 켠다.

## 6. 범위 밖, 가정, 위험

- **범위 밖**: 실시간 차단(IPS), 로그 장기 보관·검색(SIEM), 설정 자동 수정(격리 4종 제외), 규정 준수 점검, Sigma 가져오기.
  요청 본문(POST)이 필요한 공격(XXE, 저장형 XSS, 가격 변조, 웹셸 내용)과 커널 취약점 권한 상승은 로그에 남지 않아 FR-09로 '모르는 것'에 적는다.
  다른 경로의 IDOR 성공은 사이트 프로필의 `private_object_paths`에 경로를 적어야 잡는다.
- **가정**: 사용자는 최소한 CloudTrail을 켜 두었다(아니면 U3이 먼저). 원본 로그 일부를 외부 AI에 보내는 것을 받아들인다(거부하면 규칙 모드).
  비전문가에게 가장 필요한 것은 판정과 먼저 할 일이다(S3로만 확인되며 아직 확인되지 않았다).

| 판정 정확도를 우리가 만든 데이터로만 잰다 | "자기 데이터 맞춤" 지적 | 합성 세트는 회귀 하한선으로만, 독립 라벨 데이터는 따로 적음 |
| 사용자 시험 참가자를 못 모음 | S3 증명 없음 | 3명 파일럿으로 줄이고 표본이 작다고 명시 |
| 로컬 웹 화면을 공개 주소로 띄움 | 남의 로그 업로드, AI 비용 | NFR-19: 토큰 없으면 이 컴퓨터에서 온 업로드만 |
| 오탐 때문에 보고서를 안 봄 | 도구를 버림 | S7, 우리 팀 확인(FR-06) |

## 7. 검증 계획과 지금 격차

- 회차마다 `python scripts/checklist_run.py`로 자동 TC 결과를 만들고, 수동 TC는 사람이 적는다. CI는 건너뛴 테스트를 실패로 본다.
- 판정 정확도 세트에서 드러난 약점(개발 데이터): 유출 키로 객체 7개·버킷 1개 삭제는 규칙 기준(20건)에 못 미쳐 놓친다. 사무실에서 SSH 오타 2번 뒤 로그인은 '공격 의심'으로 나온다(관리자 IP를 `trusted_ips`에 적으면 빠진다).
- 프리즈 전 남은 격차: S3(사용자 평가 0회), S5(수정안 성능 미측정), S6·S7(미달), S1의 독립 라벨 데이터.
