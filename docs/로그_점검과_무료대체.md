# 로그 사전 점검·켜기와 무료 대체 수집 (2026-11-01)

> 출발점: "작은 팀은 분석할 로그 자체를 안 켜 둔 경우가 많을 것이다(추정)."
> 그래서 분석보다 먼저 **로그가 켜져 있는지 점검하고, 켜 주고, 비싼 로그는 무료 대안으로 대신**하는 기능을 넣었다.

## 1. 요금을 조사하고 보니 바뀐 판단

| 로그 | 실제 비용(us-east-1 공개 요금표) | 작은 팀 기준 판단 |
| --- | --- | --- |
| CloudTrail 관리 이벤트 | **첫 사본 무료**. S3 저장비만 든다. 최근 90일 이벤트 기록(Event history)은 **켜지 않아도 무료** | 비용 걱정할 필요 없음. 꺼져 있으면 무조건 켜게 한다 |
| CloudTrail 데이터 이벤트(S3 객체 읽기 등) | 10만 건당 0.10달러 | 민감한 버킷에만 켜도록 안내 |
| VPC Flow Logs | S3로 보내면 GB당 0.25달러(us-east-1), 서울은 0.38달러 + 저장. CloudWatch Logs는 0.50달러(서울 0.76) | 월 500만 줄이면 **월 0.2~0.3달러 정도**(어림셈). 생각보다 싸다. S3로 보내게 한다 |
| AWS WAF | 웹 ACL 월 5달러 + 규칙당 1달러 + 요청 100만 건당 0.60달러. 로그는 100만 건당 500MB까지 포함 | **가장 부담되는 항목**(최소 월 8~9달러). 여기에 무료 대안이 가장 필요하다 |
| ALB 접속 로그 | 기능 무료, S3 저장비만 | 켜게 한다 |
| GuardDuty | 30일 무료 체험 후 사용량 과금. Extended Threat Detection은 추가 비용 없음 | 켜기를 권하고, LogSight는 그 결과를 설명하는 쪽으로 |

즉 "로그를 켜면 돈이 든다"는 걱정은 **WAF에는 맞고, CloudTrail·Flow Logs에는 대부분 과장**이다.
작은 팀이 로그를 안 켜는 진짜 이유는 비용보다 "뭘 켜야 하는지 모름"일 가능성이 높다(추정).
그래서 점검 결과에 **항목별 비용을 숫자로** 같이 보여 준다.

## 2. 새로 만든 기능

### 2-1. `logsight check`: 로그 켜짐 점검 (읽기 전용)

```
python -m logsight check --region ap-northeast-2
```

| 점검 항목 | 확인 내용 |
| --- | --- |
| CT_TRAIL / CT_MULTI_REGION / CT_VALIDATION | 기록 중인 추적이 있는지, 모든 리전인지, 무결성 검증이 켜졌는지 |
| VPC_FLOW | VPC마다 Flow Logs가 있는지 |
| WAF_LOGGING | 웹 ACL마다 로그가 켜졌는지(WAF가 없으면 "해당없음" + 무료 대안 안내) |
| ALB_LOGS | ALB마다 접속 로그가 켜졌는지 |
| GUARDDUTY | 탐지기가 켜졌는지 |
| IMDSV2 | IMDSv1을 허용하는 인스턴스 |
| SG_ADMIN_OPEN | 22/3389를 0.0.0.0/0에 연 보안그룹 |

꺼진 항목마다 **왜 필요한지, 얼마인지, 무료 대안, 켜는 명령**을 출력한다. 예시: [reports/check/check_example.txt](../reports/check/check_example.txt) (가짜 AWS 계정에서 실행).

- Describe/Get/List API만 쓴다. 필요한 권한은 AWS 관리형 정책 `SecurityAudit`이면 충분하다.
- 권한이 없어 못 본 항목은 "확인불가"로 표시하고 나머지는 계속 점검한다.
- 키는 boto3 기본 방식(환경변수, `~/.aws`, SSO)을 그대로 쓰고, LogSight는 저장하거나 밖으로 보내지 않는다.

### 2-2. `logsight check --apply`: 켜 주기 (명시적 동의 필요)

```
python -m logsight check --apply CT_TRAIL VPC_FLOW GUARDDUTY
```

- 항목 ID를 직접 지정하고 `yes`를 입력해야 실행된다. 실행 전에 항목별 비용을 다시 보여 준다.
- CT_TRAIL: 비공개 S3 버킷(퍼블릭 접근 전부 차단 + 서비스별 쓰기 정책) → 다중 리전 추적 + 무결성 검증 → 기록 시작.
- VPC_FLOW: Flow Logs가 없는 VPC만 같은 버킷으로 켠다(경로 `AWSLogs/<계정>/vpcflowlogs/`).
- GUARDDUTY: 탐지기를 만들거나 다시 켠다.
- 여러 번 실행해도 중복으로 만들지 않는다. WAF·ALB는 버킷 정책이 리전마다 달라 자동 켜기 대신 명령만 안내한다.

### 2-3. `logsight collect environment`: 설정 자동 수집

```
python -m logsight collect environment --out environment.json
```

보안그룹, NACL, WAF(LockToken 포함), 인스턴스(IMDS 설정, 실제 IAM 역할 이름), 인스턴스 역할의 정책 문서, 액세스 키가 있는 IAM 사용자, CloudTrail 설정을 읽어 LogSight 형식으로 저장한다.
**"설정 스냅샷이 없으면 수정안이 0개"였던 문제(문제점 4번)를 해결**한다. 관리자 IP(`trusted_ips`)만 사람이 채우면 된다.
WAF 수정 명령에 남아 있던 `<LockToken>` 자리표시도 실제 값으로 채워진다.

### 2-4. 무료 대체 수집

| 유료 로그 | 무료 대안 | 사용법 | 한계 |
| --- | --- | --- | --- |
| CloudTrail 추적 | **CloudTrail 이벤트 기록**(최근 90일, AWS가 기본 보관) | `python -m logsight collect cloudtrail-history --days 30 --out logs/ct.json` | API가 초당 2회 제한이라 느림. 데이터 이벤트 없음. 리전별로 따로 받아야 함 |
| VPC Flow Logs | **서버 방화벽 로그**(iptables/nftables/ufw LOG) | 서버에서 `sudo bash scripts/setup_hostfw_log.sh` 후 `/var/log/kern.log`를 분석 | 보안그룹이 이미 막은 트래픽은 안 보임. 서버마다 설정해야 함. 분당 30건 제한 |
| AWS WAF 로그 | **nginx/apache 접속 로그** | `access.log`를 그대로 분석 | 탐지만 하고 차단은 못 함. POST 본문은 안 보임 |
| AWS WAF(차단) | ModSecurity + OWASP Core Rule Set | 수정안 `WEB_NO_WAF`에서 설치 방법 안내 | 오탐 조정이 필요해서 처음엔 탐지 전용으로 돌려야 함 |

새 파서와 규칙:
- `hostfw` 파서: syslog·journald ISO 시각, ufw의 `[UFW BLOCK]`, 우리 스크립트의 `LOGSIGHT-NEW` 접두어를 읽는다. 기존 VPC 규칙(포트 스캔, 관리 포트 노출)이 그대로 적용된다.
- `weblog` 파서: nginx/apache combined 형식. 시간대(+0900 등)를 UTC로 바꾼다. 기존 SQL 인젝션 패턴 규칙이 적용된다.
- 새 규칙 `WEB_PATH_PROBE`: 한 IP가 5분 안에 서로 다른 경로 20개 이상에서 404/403을 받으면 웹 스캐너로 본다(T1595.003).
- 새 수정안 `WEB_NO_WAF`: WAF가 없는 계정에서 웹 공격이 보이면 무료(ModSecurity+CRS)·유료(AWS WAF)·근본 해결(파라미터 바인딩)을 같이 제시한다.

무료 대안 로그만으로 돌린 결과(`samples/free`, 합성 데이터):

```
이벤트 72건 → 의심 46건 → 탐지 4건 → 사건 1건
INC-001 [medium] 203.0.113.50 단계=discovery→initial-access 수정안 3개
  규칙: VPC_PORT_SCAN, VPC_REMOTE_ADMIN_EXPOSED, WEB_PATH_PROBE, WEB_SQLI_PATTERN
  수정안: SG_ADMIN_PORT_OPEN, NACL_BLOCK_ATTACKER, WEB_NO_WAF
```

정상 사용자 15명(198.51.100.x)은 사건에 들어가지 않았다.

### 2-5. `logsight cost`: 비용 어림셈

```
python -m logsight cost --web-requests 3000000 --flow-lines 10000000
```

예시: [reports/check/cost_example.txt](../reports/check/cost_example.txt). 기본값(관리 이벤트 월 30만, Flow Logs 월 500만 줄, 웹 요청 100만)에서
CloudTrail 0달러, Flow Logs(S3) 약 0.22달러, WAF 약 8.60달러다. 이벤트 크기와 압축률은 추정값이다.

## 3. 검증

| 항목 | 방법 | 결과 |
| --- | --- | --- |
| 점검·켜기·설정 수집 | moto(가짜 AWS)로 빈 계정 → 점검 → 켜기 → 재점검, 22번 개방·IMDSv1 인스턴스, 역할·정책 수집 | 통과. 실제 AWS 계정은 쓰지 않음 |
| 수집한 설정으로 수정안 생성 | 자동 수집한 environment로 관리 포트 노출 사건 점검 | `SG_ADMIN_PORT_OPEN` 생성 확인 |
| CloudTrail 이벤트 기록 | API 응답을 흉내 내 저장 → 분석 | 90일 상한 적용, 원본 없는 이벤트도 처리 |
| 방화벽 설정 스크립트 | 격리된 네트워크 네임스페이스에서 iptables·nftables 각각 설치·재실행·제거 | 중복 없이 추가·제거됨 |
| 전체 테스트 | 기존 27개 + 새 9개 = 36개, Windows·macOS·Linux × Python 3.10/3.13 | 이 문서의 커밋에서 CI 확인 |

**아직 못 한 것**: 실제 AWS 계정에서 실행. moto는 실제 AWS와 응답이 조금 다를 수 있다(예: Flow Logs 대상 경로 처리). 2단계에서 팀 실습 계정으로 확인한다.
