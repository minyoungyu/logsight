# 사양서 기반 테스트 케이스 체크리스트 (v1.0, 2026-11-20)

[사양서.md](사양서.md)의 요구사항(FR·NFR)마다 테스트 케이스(TC)를 붙였다. 멘토 지시대로 **AI(Claude)로 초안을 만들고**,
사람이 실행 → 버그 수정 → 다시 실행을 돌리는 데 쓴다. 추적이 끊기지 않았는지는 `python scripts/spec_trace.py`가 확인한다.

## 1. 어떻게 만들었고, 어떻게 쓰나 (방법 제안)

### 1-1. ID로 묶는다
- 요구사항: `FR-번호`(기능), `NFR-번호`(비기능). 사양서 표의 첫 칸.
- 테스트 케이스: `TC-<영역>-<번호>`. 영역은 IN(입력), NORM(정규화), DET(탐지), INC(사건), VER(판정), TEAM, FLOW(흐름 그림), FIX(수정안), UNK(모르는 것), AI, GUARD(주입 방어), RPT(보고서), ALERT, NOTI, RESP(격리), CHK(로그 점검), ONB(설치), SCAN(웹서버 점검), HOST(서버 권한 상승), NFR.
- 한 TC는 요구사항을 하나 이상 가리킨다. 자동 TC는 `tests/파일.py::이름`을 적고, 그 이름이 코드에 있는지 스크립트가 본다.
- 테스트 코드 주석에도 TC ID를 적어 거꾸로도 찾을 수 있게 한다(예: `tests/test_freeze_gaps.py`).

### 1-2. AI로 초안을 만드는 순서 (심사 항목 'AI 활용')
1. 사양서 표 한 줄(요구사항 + 받아들이는 기준)을 Claude에 주고 "정상 1개, 경계값 1개, 실패·오탐 1개"로 TC를 뽑게 한다.
   경계값은 규칙 기준 바로 위·아래(예: 5건 걸림 / 4건 안 걸림)로 만든다. 이 체크리스트의 TC 대부분이 이 방식이다.
2. 공격 TC는 공개 기법 목록(ATT&CK, GTFOBins, OWASP 인코딩 우회)을 함께 주고 "이 규칙을 피하는 변형"을 뽑게 한다.
   11/19에 URL 조작 변형 17가지를 이렇게 만들어 5가지 누락을 찾았고, 3가지(인코딩 우회·절대 경로·권한 상승 연계)는 고쳤다.
3. 사람이 고르고 기대 결과를 확정한다. AI가 만든 기대값을 그대로 정답으로 쓰지 않는다.
4. 입력은 합성 로그만 쓰고 IP는 문서용 대역(192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24)만 쓴다.

### 1-3. 실행 → 버그 수정 반복 (심사 항목 '결과 구현 완성도')
1. **1회차:** `python -m pytest`(자동)와 아래 '수동·스크립트' TC를 돌리고 오른쪽 칸에 결과를 적는다.
2. 실패한 TC마다 GitHub 이슈를 하나 연다(제목에 TC ID). 고친 PR 설명에 같은 TC ID를 적는다.
3. **2회차:** 실패했던 TC와 같은 영역 TC만 다시 돌린다. 코드 프리즈 전날에 전체를 한 번 더 돌린다.
4. 회차마다 "TC 수 / 통과 / 실패 / 미실시"를 [코드프리즈_판단.md](코드프리즈_판단.md)의 표에 쌓는다. 최종보고서에 이 표가 그대로 들어간다.
5. 수동 TC가 자동으로 바뀌면 방법 칸을 `자동 tests/..::이름`으로 고친다(목표: 수동 비율을 회차마다 줄이기).

### 1-4. 우선순위
- **P1:** 시연 시나리오(웹 침투 → 웹셸 → sudo → 키 탈취 → S3 유출)와 보안 약속(NFR-05~08, 10). 프리즈 전 반드시 통과.
- **P2:** 나머지 기능 TC.
- **P3:** 목표 미달로 알고 있는 것(NFR-11·12·16). 결과를 그대로 적고, 프리즈를 막지 않는다.
