# 고객 인터뷰와 초기 고객(디자인 파트너) 가이드

지금 고객에 대한 근거는 문서 조사뿐이고, [문제점과_구매저항.md](../문제점과_구매저항.md)의 "안 살 이유" 중 다섯 개가 **(추정)**이다.
이 가이드는 그 추정을 실제 사람에게 확인하는 방법이다. 목표는 제품을 파는 것이 아니라 **우리가 틀린 곳을 빨리 찾는 것**이다.

## 1. 확인할 가설과 버릴 기준(미리 정함)

| # | 가설 | 이렇게 들으면 맞음 | 이렇게 들으면 틀림 → 할 일 |
|---|---|---|---|
| H1 | 작은 팀은 AWS 경보나 이상 징후를 받은 적이 있고, 그때 무엇을 해야 할지 몰랐다 | 최근 1년 안에 실제 사례를 구체적으로 말함 | 10명 중 7명 이상이 "그런 일 없었다" → 사고 후 분석이 아니라 `logsight check`(사전 점검)를 주 기능으로 |
| H2 | 경보가 왔을 때 보통 혼자 검색하거나 아는 사람에게 묻는다(전문가·외부 업체를 부르지 않는다) | "구글링", "선배에게 물어봄", "그냥 키를 지웠다" | 대부분 MSP·관제 업체가 처리 → 그 업체용 도구로 방향 전환 검토 |
| H3 | CloudTrail 말고는 로그를 거의 켜 두지 않았다(추정 3) | VPC Flow·ALB 로그를 "모름" 또는 "안 켬" | 대부분 켜 둠 → 로그 점검 기능의 가치가 낮음 |
| H4 | GuardDuty를 켜 두지 않았거나, 켰어도 결과를 읽지 않는다 | "켰는데 영어라 안 봄", "무료 기간 끝나고 끔" | 대부분 켜고 잘 처리 → "GuardDuty 다음" 메시지 재검토 |
| H5 | 로그를 외부 서비스·AI로 보내는 것을 꺼린다(추정 5) | 업로드형이면 안 쓴다, 로컬이면 쓴다 | 상관없다 → 웹 서비스로 단순화 가능 |
| H6 | 돈은 못 내도 시간을 낼 의향이 있다(추정 8) | 무료로 써 보고 30분 피드백 가능 | 시간도 없다 → 교육 시장(수업·공방전)으로 먼저 |
| H7 | AWS를 쓴다(추정 9) | 주 클라우드가 AWS | 대부분 NCP·카페24·Vercel → 대상 고객 재정의 |

**판단 규칙**: 인터뷰 10건을 채운 뒤에만 판단한다. 한두 명의 강한 의견으로 바꾸지 않는다.

## 2. 누구를 만나나

- 대상: 보안 담당자 없이 AWS로 서비스를 운영하는 2~20명 팀의 개발자·운영자. 초기 스타트업, 학과·동아리 서비스, 작은 쇼핑몰, 1인 개발자.
- 선별 질문(하나라도 '아니오'면 대상 아님): ① 지금 AWS에서 서비스를 운영하나요? ② 팀에 보안만 맡은 사람이 없나요? ③ AWS 콘솔에 직접 들어가 설정을 바꿔 본 적이 있나요?
- 목표: 인터뷰 10건, 그중 2~3팀을 초기 고객(디자인 파트너)으로.
- 찾을 곳: 학과·동아리 단체방, 교내 창업지원단 입주팀, AWS 한국 사용자 모임(AWSKRUG) 소모임, 지인 스타트업, 공방전 참가팀.

### 모집 글(예시)
> 안녕하세요, AI:ON 2026에 AWS 보안 도구를 만들고 있는 로그파인더 팀입니다.
> 보안 담당자 없이 AWS로 서비스를 운영하시는 분께 30분만 경험을 여쭙고 싶습니다. 제품 소개나 판매는 하지 않습니다.
> "AWS에서 이상한 일이 생겼을 때 어떻게 하셨는지"를 듣는 자리이고, 원하시면 무료 로그 점검 결과를 드립니다.
> 비대면 가능하고, 내용은 익명으로만 씁니다.

## 3. 인터뷰 진행(30분)

원칙: **미래·가정 질문 대신 지난 일을 묻는다.** "이런 도구가 있으면 쓰시겠어요?"는 거의 항상 "네"라서 쓸모가 없다.
제품 설명은 마지막 5분에만 하고, 그 전에는 듣기만 한다.

1. 소개(2분): 팀·서비스 규모, AWS로 무엇을 운영하는지
2. 지난 사고(10분) — H1, H2
   - "AWS에서 '어, 이상하다' 했던 가장 최근 일을 이야기해 주세요." (요금 폭탄, 키 노출 메일, GuardDuty 메일, 서버 느려짐 등)
   - "그때 처음 무엇을 하셨어요? 다음엔요?" (실제 순서를 끝까지)
   - "누구에게 물어보셨어요? 무엇을 검색하셨어요?"
   - "결국 원인을 알아내셨어요? 얼마나 걸렸어요?"
   - "그 일로 바꾼 설정이 있나요?"
3. 지금의 준비 상태(8분) — H3, H4
   - "CloudTrail·VPC Flow Logs·ALB 로그·GuardDuty 중 켜져 있는 걸 아시나요?" (모르면 모른다고 적는다)
   - "GuardDuty 메일이나 결과를 마지막으로 본 게 언제예요? 그때 어떻게 하셨어요?"
   - "보안에 한 달에 얼마나 쓰세요? (돈, 시간)"
4. 신뢰·방식(5분) — H5, H7
   - "로그를 외부 서비스에 올려 분석하는 것에 대해 팀에서 정한 게 있나요?"
   - "AWS 말고 쓰는 클라우드가 있나요?"
5. 짧은 시연과 부탁(5분) — H6
   - 샘플 보고서 한 장을 보여 주고 "어디가 이해가 안 되세요?"만 묻는다(좋다/나쁘다 질문은 하지 않는다).
   - "다음에 실제 계정에서 `logsight check`를 같이 돌려 보고 30분 피드백을 주실 수 있나요?" → 초기 고객 후보

## 4. 초기 고객(디자인 파트너) 제안

- 우리가 주는 것: 무료 사용, 로그 점검 결과와 "켜야 할 로그" 목록, 원하면 지난 사고 하나를 같이 재분석.
- 부탁하는 것: 4주 동안 두 번(점검 1회, 사고 재분석 또는 모의 시나리오 1회) 30분 피드백, 익명 사례로 써도 되는지 동의.
- 지키는 것: **AWS 키를 받지 않는다.** 고객이 자기 컴퓨터에서 읽기 전용으로 직접 돌리고, 결과 화면만 함께 본다.
  로그 원본은 우리에게 보내지 않는다. 받은 경우 분석 후 바로 지우고 지운 사실을 알린다.
